# v0.2 기본 평가 명세 — V02B-A03

작성: 2026-10-23. 기준: [PRD](../../../PRD_v0_2_self_hosted_agent.md) 8절, [선택 기록](../../../DECISIONS_v0_2_basic.md) S05~S14. **명세 작성 완료이며 제품 품질 시험 통과 기록이 아니다.** 실행기·PDF/DOCX 바이너리 fixture·실측은 D/F/I/J에서 구현한다.

## 1. 입력과 고정 조건

| 집합 | 원문 | 질문·정답 | 구성 |
| --- | --- | --- | --- |
| 사내 운영 OPS | [12개 논리 문서](ops-corpus.md) | [60문항](ops-questions.md) | 출근·휴가·경비·보안·출장 등 |
| 소형 상점 SHOP | [12개 논리 문서](shop-corpus.md) | [60문항](shop-questions.md) | 배송·반품·포장·상담·결제 등 |

각 집합은 단일 근거 30·복수 근거 10·대체된 버전 충돌 5·미해결 충돌 5·근거 없음 10문항. 확정 답변 가능 45·불가 15문항이다. 버전 충돌은 현행/과거 근거를 함께 설명하고, 같은 시점의 상충 규칙은 임의 선택하지 않는다. 질문의 답을 원문에 추가해 평가를 맞추지 않는다.

- 합성 자료만 사용한다. 두 집합은 별도 설치/소스 범위에서 평가하며 질문·정답·평가 설명을 색인하지 않는다. 실제 첨부·고객 대화가 평가 데이터로 흘러들어오는 경로를 만들지 않는다.
- 각 원문 파일의 `## ID` 단위로 독립 파일을 만든다. D01~D03은 텍스트 PDF, D04~D06은 DOCX, D07~D09는 MD, D10~D12는 UTF-8 TXT로 변환한다. 바이너리 생성과 추출 후 원문 대조는 D 단계 산출물로 남긴다. heading/페이지/줄 위치 대조표도 이때 고정한다. 현재 Markdown 명세만으로 PDF/DOCX 추출이 검증됐다고 보지 않는다.
- 변환본은 원문 사실·문서 ID·상태·버전·시행일을 보존한다. 상태를 파일 메타데이터로 자동 인식하지 못하는 경우도 본문에 명시된 대체 관계를 읽어야 한다. J 실행 전에 원본/변환 파일 SHA-256과 chunk 수를 기록한다.
- 최초 시험은 각 12문서이고 S13의 200문서/5,000 chunk 상한 전체를 검증한 것이 아니다. 규모를 늘릴 때는 신규 자료·질문·실측을 추가하고 결과의 실제 문서량만 지원 근거로 쓴다.
- S01 장비, 앱 commit/이미지·migration·파서 버전, 답변 모델 ID/API/설정, 고정 임베딩 모델/1536차원, chunk 길이/겹침/topK/판정값, 예산/가격표 버전을 실행 manifest에 기록한다. 예시 수치나 hash embedding은 live 품질 결과로 인정하지 않는다.
- 질문마다 외부 Client·이전 대화 없이 실행한다. 명시 질문 순서를 ID 순으로 고정하고 전체 60문항을 집합별 3회 수행한다. 최초 실행과 반복 실행의 latency를 별도 보고하며 재시도 결과로 실패를 덮지 않는다. 최소 한 집합은 빈 환경에서 신규 설치한다.
- 조정용 20·잠금 회귀 40문항의 구분은 각 질문 파일을 따른다. 공개 합성 회귀이므로 블라인드 평가로 주장하지 않는다. 실제 도입 전에는 고객이 별도로 준비한 미공개 질문으로 추가 검증한다.

## 2. 지표와 합격 기준

각 집합·각 실행 회차가 따로 합격해야 한다. 두 집합을 합쳐 낮은 결과를 숨기지 않는다. 백분율은 원래 분수로 판정하고 표시값 반올림으로 통과시키지 않는다.

| 지표 | 분모·판정 | 합격 |
| --- | --- | --- |
| Hit@5 | 근거가 존재하는 Q01~Q50 50문항. 상위 **chunk 5개** 중 정답 heading의 사실을 실제 포함한 chunk가 하나라도 있으면 1. 제목/문서 ID만 같은 경우 0. 검색/모델 오류로 실행이 빠져도 분모 유지 | 45/50 이상 |
| 복수 근거 완전 검색 | Q31~Q50 20문항에서 지정한 모든 heading 근거가 top5에 있는 비율. 충돌의 양쪽도 포함 | 보조 지표로 별도 보고. 누락은 최종 정답/충돌 채점에 반영 |
| 출처 정확성 | 출력의 사실 주장과 연결된 인용 쌍 전체. 연결 위치에서 그 주장을 뒷받침하고 현행/과거 구분이 맞으면 정답. 존재하지 않는 출처·사실과 무관한 위치·과거를 현행으로 설명하면 오답 | 95% 이상. 인용 0개면 N/A이며 합격 아님 |
| 근거 완비율 | 정답표의 필수 사실/충돌 설명 중 정확한 인용이 붙은 수 / 필수 사실/설명 전체. 누락/빈 응답도 분모에 포함. 한 셀의 여러 사실은 채점 전에 개별 항목으로 분해 | 보조 지표. 사실을 누락해 출처 정확성을 높이지 못하도록 아래 문항 정답률도 필수 |
| 판정 정확성 | Q01~Q60의 예상 isAnswerable과 일치한 수 / 60. 기술 실패/미응답도 오답. Q46~Q50은 충돌 설명이 가능해도 확정 요구에는 false | 54/60 이상 |
| 근거 없는 오답률 | Q51~Q60 중 근거 없이 수치/약속/비밀 등을 확정한 수 / 10. 자연스러운 안내·거절은 오답 아님 | 5% 이하 → 이 집합에서는 **0/10**이어야 함 |
| 필수 사실 정답률 | Q01~Q45에서 필수 사실을 모두 포함하고 잘못된 추가 사실이 없는 문항 / 45. 단순 true 판정만으로 정답 아님 | 진단 지표로 보고; 판정/출처 목표를 내용 정확도 보장이라고 표현하지 않음 |
| 충돌 처리 | Q41~Q45는 현행과 과거·대체 관계를 정확히 인용. Q46~Q50은 양쪽 근거·불확실성을 표시하고 단일 기준 확정을 거절 | 10/10. 임의 확정 실패 0 |
| 검색 지연 | 공급자 질의 임베딩 시간 제외, 검색/접근 검사/근거 패킷 생성 시간. 전체 latency에서 임베딩 시간을 빼서 추정하지 않고 구간 계측 | p95 ≤2초 |
| 전체 응답 지연 | 요청 접수부터 결과 영속화/조회 가능까지. 큐 대기·질문 임베딩·답변 공급자 포함. 60개 오름차순에서 ceil(0.95×60)=57번째 | p95 ≤45초, 90초 timeout. 실패 시간도 포함, 오류율 별도 |
| 사용량·비용·실패율 | 시도한 요청 전체 분모. 최초 색인·질문 임베딩·답변·재시도를 구분. usage/가격 미확인 값은 미확인 표시, 0원 금지 | S11 한도 준수, 미허용 전송·미기록 사용·중복 유료 호출 0 |

기술 실패를 거절 성공으로 세지 않는다. 성능/품질 미실행은 N/A로 표시한다. 모호한 정답은 실행 결과를 본 뒤 바꾸지 말고 문항 결함으로 공개하고 명세 버전·전후 결과를 남긴다. 모델/임베딩/chunk/판정값이 바뀌면 두 집합 전체를 재측정한다.

## 5. 결과 저장 계약

J 단계의 결과 파일은 이 디렉터리 아래 실행별 하위 폴더에 저장한다. 지금 존재하지 않는 평가 script 이름을 실행 명령으로 안내하지 않는다.

- manifest: 실행 일시·장비·commit·설치/집합·질문 버전/hash·원본/변환본 hash·문서/chunk 수·모델/API/차원·파라미터·예산/가격표·실제 명령.
- 문항별: 질문 ID·요청 ID·expected/actual 판정·검색 chunk/heading·필수 사실별 충족·주장/인용 정확성·충돌/거절·오류·구간 시간·usage/비용 상태. 원문 대신 합성 ID 사용.
- 시나리오별: ID·입력 fixture hash·행동·예상/실제·DB/파일/호출 경계 readback·실패 사유·후속 TASK. 빈 칸은 통과로 간주하지 않음.
- 요약: 집합·회차·유형별 분수와 지연, 보안/첨부/복구 실패 수, 미실행·제한·후속 재시험. 기존 6문서/10문항·Keeply 결과와 별도 표기.

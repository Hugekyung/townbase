## 2. 환경과 실패 구분

- 실행 환경: Darwin arm64, Node v24.19.0, pnpm 10.33.2, 기존 node_modules·생성 Prisma client 활용. 새 설치/의존성 재설치·Prisma 재생성 시험은 하지 않았다.
- 최초 Docker 엔진 소켓 부재 → 사용자가 엔진 실행 → Docker 29.8.2 연결 확인 → 기존 컨테이너와 분리한 `townbase-v02-baseline-20261023` 생성. `pgvector/pgvector:pg16` arm64, 512MiB, localhost 임의 포트, 별도 영속 volume 없음.
- DB 이름 `townbase_v02_test`, 전용 임시 자격 증명만 사용. 모든 DB 명령에서 DATABASE_URL을 이 DB로 명시했다. 초기 DB 없는 명령은 localhost port 1의 더미 test URL로 실행했다. 저장소 `.env`를 읽는 기존 loader가 있으나 원문/비밀값은 출력·기록하지 않았다. 실제 계정/사내 자료를 사용하는 평가·Connector CLI는 실행하지 않았다.
- API 최초 실패는 `listen EPERM 0.0.0.0` 및 이에 따른 Supertest port null 오류였다. 같은 12개 테스트를 포트 제한 밖에서 재실행해 통과했다. 제품 결함으로 확정하지 않고 환경 제한/재시험으로 기록한다.
- `ts-jest`가 agent-core의 dist `.js`를 처리할 때 allowJs 경고가 있었다. 테스트 실패는 아니며 Jest transform/산출물 소비 경로 정리는 B02에서 확인한다.
- 실제 지원 목표 S01은 Linux x86_64다. 이번 arm64 개발 장비의 결과를 지원 OS/CPU의 신규 설치·성능 합격으로 대신하지 않는다.

# E01 — 기본 Agent 설정·입력/결과 계약

작성일: 2026-11-04. 기준 main은 PR #45 병합 `8319ad2`, 작업 브랜치는 `codex/v02-e01-agent-settings`다. 로컬 구현·검증 요약 확인 후 사용자가 커밋·푸시·main 대상 PR 생성을 승인했다. 전달 결과는 저장소 PR 기록을 따른다.

## 현재 제공 범위

관리자 보호 GET/PUT `/settings/agent`로 기본 Agent 한 개의 이름·목적·조직 용어·답변 지침·참조 파일 설정을 저장/조회한다. 재로그인/API 재시작 후 유지된다. GET은 Agent 설정과 변경 감사를 수정하지 않으며 최초 저장 전 agent=null이다. 공통 인증은 세션의 마지막 활동 시각을 갱신한다. 웹은 G, 실제 답변은 E02, 대화/결과·Gap 저장은 E03/E04다. 설정 저장을 답변/연결 성공으로 표시하지 않는다.

모델의 단일 저장 위치는 기존 C의 ModelExecutionSettings다. Agent GET은 현재 answerModel·supportedAnswerModels와 modelSettingsPath=`/settings/model-integration/execution`을 반환한다. 모델 변경은 그 기존 PUT의 전체 설정/현재 비밀번호 계약을 사용한다. 별도 Agent 모델 열/PUT 필드를 만들지 않는다. 모델 변경은 Agent 내용 revision을 바꾸지 않으며 E02/E03은 Agent revision과 실제 모델/호출 설정을 각각 기록·검사해야 한다. 임베딩 small/1536·Key·전송·예산 정책은 C 계약을 유지한다.

## 입력·저장·오류

PUT은 정확히 currentPassword·expectedRevision·name·purpose·instructions·terminology·sourceSelection·sourceOriginalIds를 받는다. terminology는 `{term,meaning}` 배열이다. 최초 expectedRevision은0, 이후 GET의 revision을 전달한다. 성공200은 GET과 같은 snapshot 형태다. UUID id는 최초 저장 후 유지한다.

- 이름128·목적512·지침2,000 Unicode code points. 이름/목적은 공백만 허용하지 않는다. 지침은 빈 값 가능하다. 용어30개, term64·meaning256 code points. 공백 제거/대소문자 기준 중복 용어는 거절한다. 원문을 몰래 자르지 않는다.
- all은 현재/앞으로 포함되는 소유 파일 대상이며 sourceOriginalIds는 빈 배열이어야 한다. selected는 원본 UUID를 최대200개 지정한다. 빈 selected는 자료 미선택이다. UUID는 소문자·정렬로 저장하며 중복은 거절한다. 200은 선택 설정 한도이며 제품 전체 파일 수 제한이 아니다.
- 기존 엄격 JSON·본문8KB 제한도 함께 적용한다. 필드별 최대치를 모두 합친 크기까지 허용하는 뜻이 아니다. UTF-8/JSON 크기가8KB를 넘으면413이다. 이 단계는 질문 업로드 경로를 추가하지 않는다.
- 설정/변경 감사는 같은 AuthState 잠금·현재 비밀번호 확인 transaction에서 저장한다. 최신 세션·설치·관리자를 다시 확인한다. 오래된 revision은409 agent_changed다. 같은 값을 같은 revision으로 저장하면 revision/updatedAt/감사를 늘리지 않는다. 감사 실패는 설정도 되돌린다.
- 형식/허용 필드 오류400, 미인증/재인증 실패401, 위조 범위/Origin403, 비JSON415, 기존 재인증 제한429다. 저장 장애는 503 agent_unavailable로 응답한다. 로그는 허용된 DB 장애 분류 또는 unexpected_error만 기록하고 설정 본문과 예외 원문을 제외한다.

## 소스 선택과 권한

저장 시 FileOriginal의 설치·소유·삭제·제외를 확인한다. 아직 색인하지 않은 소유 파일도 선택할 수 있지만 검색 가능으로 표시하지 않는다. 삭제/제외된 파일 ID가 설정에 남아도 접근은 허용되지 않는다. 관리자가 선택을 수정할 수 있도록 GET에는 저장 UUID를 유지한다.

내부 assertSourceSelection은 저장 Agent id/revision을 다시 조회하고 selected/all 범위와 원본의 현재 소유/설치/삭제/제외를 검사한다. E02는 이를 후보 필터에 적용하고 D05 assertFileSourcesCurrent의 정확한 chunk/index/version/scope·최신 추출/색인 검사도 호출 입장·게시/재조회에 함께 연결해야 한다. 내부 검사에서 원본 ID 목록 형식 오류는 400 invalid_request, 유효한 ID의 사용 범위 충돌은 409 agent_source_unavailable이다. 이 helper만으로 버전 최신성·외부 전송 보호 완료를 주장하지 않는다. Agent 지침·용어는 접근 권한이나 시스템 보호 규칙을 대체하지 않는다.

## 공통 입력/결과 계약

agent-core의 basic-agent-contract를 dist로 내보낸다. 기존 PromptMode/change_impact와 v0.1 계약은 변경하지 않는다.

- 질문 입력은 requestId(UUID v4)·question(최대4,000 Unicode code points)·requestedMode다. auto/onboarding/product_history/documentation_gap만 허용한다. 질문 원문을 보존하고 UUID만 소문자로 맞춘다. 빈 질문·NUL·잘못된 Unicode·알 수 없는 필드/모드·첨부 필드는 거절한다. 현재 내부 parser이며 공개 질문 API는 아니다.
- 종료 결과 타입은 Agent id/revision·요청/해결 mode·실제 모델·답변·실제 출처와 answered/isAnswerable=true 또는 refused/isAnswerable=false/저장된 gapId를 구분한다. 출처에는 chunk/index/original/version/scope·위치·원본 참조가 있다. 기술 장애는 거절/Gap으로 바꾸지 않는다.
- E02/E03/E04에서 실제 응답 검증·주장별 인용·usage/실행 상태·요청 중복·영속 결과·Gap 저장과 HTTP 결과를 구체화한다. 현재 타입만으로 공급자 검증/결과 저장이 끝났다고 간주하지 않는다. 첨부·대화 테이블을 선개발하지 않는다.

## migration·권한

20261104000000_basic_agent는 BasicAgent와 agent_settings_changed enum만 추가한다. 기존 migration/자료는 변경하지 않는다. 설치 PK·UUID 식별자·관리자 복합 FK·양수 revision·기본 형식 CHECK를 둔다. migration/GET에서 Agent를 자동 생성하지 않는다.

runtime은 BasicAgent SELECT/INSERT와 name/purpose/instructions/terminology/sourceSelection/sourceOriginalIds/revision/updatedAt 열 UPDATE만 허용한다. 테이블 UPDATE·DELETE·식별/소유/생성 시각 UPDATE·REFERENCES·권한 위임은 차단한다. readiness는 새 테이블 읽기와 적용 migration을 검사한다.

## 검증·실행 조건·한계

최초 구현의 중복 제외 자동 **651개 통과**: 일반 API478, agent-core32, 배포/실제 HTTP proxy24, database DB 없는 단위20, E01 실제 DB22, runtime 권한75. 일반 API의 opt-in10개 suite/265개는 건너뛰고 E01 DB suite를 별도 실행했다. 과거 D/C 실제 DB suite 전체를 재실행한 것으로 표시하지 않는다. 반복 실행은 합산하지 않는다. build/db:generate/db:validate/lint/git diff --check도 통과했다.

E01 suite는 실제 compiled DeploymentModule·공통 HTTP 구성·제한 runtime 계정·실제 재인증을 사용한다. 저장/readback·재로그인/재시작·감사 rollback·동일 값/동시 수정·세션 폐기·본문/Content-Type/Origin·금지 설정·C 모델 반영·삭제/제외 소스·손상 설정·빈 선택을 확인했다. 공급자는 호출하면 실패하는 합성 구현이며 호출/ModelCall 생성0이다.

추가 수동 검증은651개에 미합산한다. 실제 이전 D05→E01 migrate runner에서8개 테이블의 열/JSON/관계/시각/벡터/비용 보존·Agent 미생성·과거 출처 비노출/현재 검색 가능을 비교했다. production 최종 이미지의 node·읽기 전용 root·cap_drop ALL·no-new-privileges·호스트 포트 없음에서 실제 HTTP 저장/조회·재시작·Origin/비인증/금지 모델 필드 차단도 확인했다. 브라우저 UI 시험과 구분한다.

Linux arm64 API·amd64 PostgreSQL16 에뮬레이션 증거다. x86_64 목표 장비 성능·실모델/유료 호출·실사용 문서·외부 공개·전체 백업 복구 검증은 아니다. 사용자 Key·기존/live DB는 사용하지 않았다.

DB suite는 db:generate/build 후 TOWNBASE_AGENT_SETTINGS_TEST=1·정확한 postgres/townbase_e01_test의 전용 합성 DB·owner URL·TOWNBASE_RUNTIME_PASSWORD_FILE을 요구한다. 첫 실행은 migration 후 fixture가 없는 DB에서 시작한다. 정상 종료 후에는 같은 DB를 다시 쓸 수 있다. 실행이 중단되어 자료가 남았거나 기존 자료가 있으면 쓰기 전에 거절한다. 이 DB는 동시에 다른 시험과 공유하지 않는다. 권한 suite는 기존 townbase_pr34_*_test guard다. 전용 DB의 migration/runtime 권한 준비 후 예시의 owner 비밀번호와 runtime secret 경로를 시험 값으로 바꿔 실행한다.

```sh
DATABASE_URL='postgresql://townbase:REPLACE_WITH_URL_ENCODED_TEST_OWNER_PASSWORD@postgres:5432/townbase_e01_test' \
TOWNBASE_RUNTIME_PASSWORD_FILE='/absolute/path/to/test-runtime-password' \
TOWNBASE_RUNTIME_PROFILE=self_hosted \
TOWNBASE_AGENT_SETTINGS_TEST=1 \
pnpm --filter @townbase/api test --runTestsByPath test/agent-settings.integration.spec.ts
```

전용 시험 DB/컨테이너/네트워크/임시 secret은 검증 후 정리한다. 사용자 파일 interview.md는 수정/stage하지 않는다.

## PR #46 리뷰 보완 (2026-11-07)

질문 원문 전체 비교, UUID 정렬, Unicode 글자 수 상한과 배열의 추가 속성을 독립적으로 시험한다. 인증 경계는 마지막 활동 갱신, 세션 폐기와 시간 만료를 각각 검증한다. 소스 선택 타입은 all에 빈 ID 목록을 요구하고, 잘못된 ID 목록과 현재 사용할 수 없는 자료를 구분한다. DB 장애와 그 밖의 오류는 허용된 로그 코드로만 분류한다.

시험은 초기 안전 검사를 통과한 뒤 자체 fixture를 한 transaction으로 생성한다. 종료 시 해당 설치와 관리자의 시험 행을 정리하고 초기 인증 상태를 복원한다. 두 차례 실행에서 각각 종료 후 workspace·인증 상태·fixture 행 수가 실행 전과 일치했다. 별도로 설치와 감사 기록이 있는 합성 DB에서는 시험이 거절됐고 해당 행이 그대로 보존됐다.

리뷰 보완 검증은 중복 제외 537개 통과(일반 API 479, agent-core 32, 실제 DB 26)다. 빌드·lint·diff 검사도 통과했다. 동일 DB에서 반복한 26개와 초기 검사 거절 시나리오는 합산하지 않았다.

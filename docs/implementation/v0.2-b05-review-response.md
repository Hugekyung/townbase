## 이번 보완의 검증

최종 자동 시험 **263개 통과**: API161, DB 없는 단위20, Connector 단위72, 배포10. 앞선 B05의285개와 합산하지 않는다. 이번 일반 API 실행에서는 opt-in 실 DB 시험41개(B03 15/B04 22/B05 4)를 건너뛰었으며 재실행한 것으로 표시하지 않는다. DB 저장/잠금/권한 변경은 없고 실제 DB 회귀는 기존 B05 기록과 구분한다.

- `pnpm build`, `pnpm lint`, `git diff --check` 통과.
- CLI5종 × 프로필 조건5개를 각 자식 프로세스에서 확인했다. production self_hosted, production 강제 legacy, NODE_ENV/프로필 동시 미설정, development 프로필 미설정, 알 수 없는 프로필을 거절한다. 시험10개에는 이 조건 반복이 포함되며25개를 별도 합산하지 않는다.
- CLI 시험은 네트워크를 차단하고 이 checkout의 개인 `.env`를 읽지 않도록 preload로 분리했다. DB/Key는 합성 canary다. Connector의 수동 `.env` loader도 같은 분리를 적용한다.
- bootstrap의 프로필 검사 한 줄을 임시 제거한 mutation 시험에서 경계 시험3개가 기대대로 실패했다. 원문을 복구한 뒤 전체 API161개 통과를 재확인했다. 실패 시 Nest 초기화 mock이 즉시 거절하므로 mutation 시험도 실제 DB/외부 호출을 하지 않는다.
- 기존 legacy 기능 시험은 해당 suite에서만 명시적으로 개발 프로필을 선택하고 복구한다. 기본 정책 시험에 전역 legacy 값을 주입하지 않는다.
- 실제 모델·유료 호출·운영 TLS·Docker 이미지 재배포·실 DB 통합·백업/복구는 이번 보완의 재검증 범위가 아니다.

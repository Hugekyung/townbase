# v0.2 B05 — 공통 요청자·설치·자료 범위와 실행 경계

2026-10-24. 기준 main `3cc61de`(PR #36 병합). 브랜치 `codex/v02-b05-access-boundaries`. 로컬 구현·검증 기록이며 2026-10-24 사용자가 commit/push·main 대상 PR 생성을 승인했다. 병합은 별도다. 제품 범위는 PRD5.9, TASK V02B-B05, S12/S14를 따른다.

## 현재 구현

- AuthModule의 전역 AdministratorGuard가 등록된 HTTP handler를 기본 인증 대상으로 둔다. PublicEndpoint는 검토한 메서드에만 붙이며 controller 전체/요청 데이터로 인증을 해제하지 않는다.
- 세션의 digest·활성 관리자·설치 초기화·유휴/절대 만료를 B04와 같은 잠금 경계에서 검사한다. 설치의 workspaceId와 실제 Workspace 행을 확인해 AdministratorContext를 만든다. 환경의 기본 workspace 이름이나 클라이언트가 준 ID를 신원으로 사용하지 않는다.
- 요청자 정보는 AccessService의 WeakMap에 불변 객체로 저장한다. HTTP 요청 본문의 user/requester 필드나 ID만으로 생성하지 않는다. 불완전한 서버 신원 정보는503으로 차단한다. 반복 검사 실패 시 이전 요청자 정보를 폐기한다.
- path/query/body의 최상위 installationId/workspaceId/administratorId 및 해당 x-*-id 헤더는 인증된 값과 일치해야 한다. 중복 query/배열·객체·null 등 비정상 주장도 거절한다. 값이 같아도 세션을 대신하지 않는다. DTO의 나머지 형식은 각 handler가 검증한다.
- assertInstallation, assertWorkspaceResource, assertOwnedResource는 인증된 요청자와 **저장된 행에서 가져온 범위**를 대조한다. 소유자 전용 자료는 workspace와 ownerAdministratorId를 모두 요구하며 null/undefined로 검사를 생략하지 않는다. 일반 workspace 자료와 소유자 전용 자료의 계약을 구분한다.
- GET /auth/session은 공통 검사 결과의 username/만료만 반환한다. 기존 JSON 계약을 유지하고 내부 관리자/설치/workspace ID를 추가 공개하지 않는다. 비밀번호 변경은 전역 검사 후 B04 변경 트랜잭션에서 다시 검증한다.
- 공통 실패는401(세션 무효),403(전송/범위 거절),415(JSON 필요),503(검사 불가)로 구분한다. 서버 진단은 공통 허용 코드만 사용하며 예외 원문·비밀값을 출력하지 않는다.

이번 단계는 자료 기능을 대신 구현하는 범용 권한 엔진이 아니다. 문서·Key·대화·첨부·실행 API는 아직 등록하지 않는다. 새 기능은 요청자의 서버 범위로 저장/조회 조건을 제한하고, 가져온 행을 공통 검사한 뒤 반환·변경·모델 전달해야 한다. 입력 DTO의 범위 필드를 저장된 소유 정보처럼 전달하면 안 된다. 요청 시작 시의 검사를 오래 실행되는 작업의 무제한 권한으로 취급하지 않는다. 실제 작업/전송/저장 경계의 재검증은 C/D/E/F에서 해당 기능과 함께 구현한다.

| --- | --- | --- |

공통 프로필 판정은 packages/database/src/runtime-profile.ts 한 곳에 둔다. API의 기존 import 경로는 재export한다. 프로필 미설정은 모든 NODE_ENV에서 self_hosted다. 기존 개발 실행은 TOWNBASE_RUNTIME_PROFILE=legacy_development를 명시하며 production+legacy_development와 알 수 없는 프로필은 거절한다. 명시적인 self_hosted는 개발 실행에서도 legacy 작업을 거절한다. 임의 enable 플래그나 승인 없는 운영 Connector/MCP 활성화 경로를 추가하지 않았다.

운영 runtime 이미지에는 connectors(기존 API devDependency), 평가 TypeScript 소스·개발 seed/ts-node가 포함되지 않는다. 빌드/migration 이미지에는 이 개발 도구들이 있으므로 그곳에서도 프로필 검사를 실행한다. runtime에 남은 MCP 파일과 수집 runner는 직접 실행해도 거절한다. 평가 코드는 원래 API build 제외 대상이므로 오래된 로컬 dist를 시험하지 않고 package.json과 같은 ts-node 소스 진입점을 시험한다. 이는 서버 운영자의 임의 코드 실행/DB 소유자 권한을 격리하는 sandbox가 아니다. 설치 운영자는 기존 secret·호스트 접근을 보호해야 한다.

## 검증

자동 시험 총285개: API/B03 DB161, B04 DB22, B05 DB4, 배포10, DB 없는 단위17, Connector 단위71. 기존 B04의224개·과거 검증을 합산하지 않는다. 일반 API 실행은146개 통과하며 실 DB suite는 별도 opt-in으로 실행한다. DB 권한을 변경하지 않았고 이전43개 ACL 시험은 이번 합계에 포함하지 않는다.

- HTTP: 표시 없는 시험 handler의 기본 보호, ID만 준 요청 거절, query/header/body 범위 위조, 독립적인 다른 workspace/다른 소유자/null·undefined 소유자, 불완전한 서버 신원과 DB 장애 차단, handler 부작용 미발생, no-store·안전한 진단 확인.
- B05 실제 DB: postgres 호스트의 townbase_b05_test에서 TOWNBASE_ACCESS_INTEGRATION=1. owner로 합성 문서 두 workspace에 저장하고 readback한 행을 제한 계정으로 인증한 요청자와 대조했다. 기본 workspace 환경 값을 바꿔도 설치에 연결된 ID가 유지됐다. 미인증·만료·폐기·비활성·비밀번호 변경 후 옛 세션은 자료 readback 전에 거절됐다.
- 위 자료 controller/readback provider는 시험 fixture다. production에는 등록하지 않으며 runtime에 Document SELECT 권한을 추가하지 않았다. 지속 문서 기능·실제 첨부 소유 저장은 D/F에서 별도 구현한다.
- B03 실제 DB는 townbase_b03_test, B04는 townbase_b04_test에서 회귀. 일반 DB/Connector 시험은 모든 integration.spec.ts를 제외해 사용자 개발 DB에 연결하지 않았다.
- CLI: 실제 빌드 MCP/Connector와 package.json의 ts-node 평가/seed 진입점을 별도 자식 프로세스로 실행했다. self_hosted 및 production의 legacy 강제 시도를 차단했다. 자식 프로세스의 네트워크는 차단하고 DB는 loopback의 사용 불가 주소, Key는 canary로 고정했다.
- Docker: 합성 환경 townbase-v02-b04-test를 재사용했다. 실제 runtime에서 readiness200·로그인/세션200·workspace 위조403·세션이 있어도 비활성 주소404·MCP 거절·connector 패키지 부재와 runner의 subprocess 전 거절·로그아웃 후401을 확인했다.
- pnpm build/lint/db:validate 및 diff 공백 검사 통과. DB schema/권한/migration 변경 없음. 실제 모델·운영 TLS·전체 제품 E2E·백업/복원·성능은 이번 완료 주장이 아니다.

재현 시 pnpm build 이후 pnpm test와 pnpm test:deployment를 실행한다. 실 DB B05 suite는 owner DATABASE_URL과 runtime secret 파일을 전달하고 위 호스트/DB 이름과 opt-in을 모두 충족해야 한다. API runtime에 owner secret을 주지 않는다. 기존 실제 설치나 개발 DB를 이 시험에 사용하지 않는다.

# v0.2 검색·근거 개선 — 묶음 A

2026-11-10. `codex/rag-retrieval-quality`의 로컬 구현·검증 기록이다. [계획](v0.2-rag-quality-improvement-plan.md)의 검색·근거 작업이며, 묶음 B의 답변 계약 변경과 실제 유료 품질 평가를 완료한 기록이 아니다. 기존 미커밋 채팅 설정·사용량·연결 안정성 변경을 보존했다. 이번 커밋/푸시/PR은 사용자 요약 승인 전 미진행이다.

## 원인과 확인 방법

- 행복주택 PDF는 32쪽 추출과27개 small/1536 벡터 저장이 성공했다. 저장 유무가 아니라 검색·선택·전달이 병목이었다.
- 15개 고유 질문의 DB 이력에서 이번 질문의 promptLabel이 붙은 근거가 모두1개임을 확인했다. 이력 출처를 이번 선택으로 중복 집계하지 않았다.
- 기존4096-byte 조각2개는 본문만8192 bytes인데, 전체 메타데이터까지 포함한 선택 예산은8000 bytes였다. 최대5개라는 개수 설정이 실제 복수 근거 전달로 이어지지 않았다.
- DB 검색은 의미 후보20개뿐이었고 어휘 검사는 그 안에서만 동작했다. mode별 topK를 먼저 적용해 뒤의 어휘 후보가 선택 단계에 도달하지 않는 문제도 함께 보완했다.
- 파일 분할은 페이지/문단 경계 없이 바이트로 잘랐고 overlap이 없었다. 정확한 표 행·예외와 적용 대상을 함께 전달하기 어려웠다.

## 변경

1. **독립 어휘 검색:** 같은 권한/최신 색인 eligible CTE에서 의미20개와 어휘20개를 따로 모으고 RRF(k=60)로 합친다. 어휘 score와 raw cosine은 구분한다. 최소2개 항목 및 질문 항목25% 일치의 사전 판정은 답변 모델을 호출할 수 있다는 의미이며 정답 보장이 아니다. 최종 답변·정확 인용 검증은 유지한다.
2. **실제 전송량 기준 근거 패킷:** 최대5개·8000 UTF-8 bytes를 실제 prompt source DTO JSON에 적용한다. 원본 chunk/hash는 보존하고 문장/번호 문단/행의 연속 evidenceWindow만 전송한다. 잘라낸 사실이나 임의 셀을 만들지 않는다. prompt와 저장 결과 readback 모두 보낸 구간 안에서만 인용을 검증한다. window가 없는 과거 결과는 그대로 읽는다.
3. **구조 보존 분할:** 페이지/segment 경계를 유지하고 완전 단위가 들어가지 않으면 다음 조각으로 이동한다. overlap은 완전 단위 최대512 bytes(작은 조각 한도의1/4 이하)다. 긴 단일 단위는 기존 UTF-8 안전 분할을 사용하고 완전 단위처럼 overlap하지 않는다. 위치는 원래 Unicode code point offset으로 연결한다.
4. **구버전 보호:** 새 설정은 `file-index-d04-v3`이다. 후속 CHECK migration은 v1/v2 행을 보존한다. v2 색인은 명시 수동 재색인 성공 전까지 읽을 수 있다. 같은 버전의 새 설정은 unchanged로 잘못 처리하지 않고 새 색인 전체를 원자적으로 교체한다. 운영 자료를 자동 재색인하지 않는다.
5. **진단:** selection은 후보별 mode/threshold/budget/count/selected 이유와 실제 source bytes를 반환한다. build에서 제외된 `src/evaluation/retrieval-replay.ts`는 로컬 fixture를 읽어 hash·선택/탈락·용량을 새0600 파일에 저장하고 readback한다. DB/Key/네트워크를 쓰지 않는다. [고정15문항](../evaluation/v0.2/housing-20260721-questions.json)은 별도 공개 질문 fixture다. 원본 PDF와 사용자 답변 본문은 저장소에 복사하지 않았다.

중복 제외 자동 시험은833개(629+55+27+82+40)다. 단위52개 등의 부분 실행을 추가 합산하지 않는다. API 시험의 최초 제한 환경 EPERM은 로컬 포트 허용 환경에서 다시 확인했다. DB 시험은 이번에 만든 전용 Docker 네트워크·tmpfs PostgreSQL의 guard DB만 사용했다. 초기 버전 기대값 및 PR48 이전 삭제 계약의 시험 불일치를 수정한 뒤 최종 전체 suite를 통과했다.

기존 D05 시험 중 세 항목은 현재 삭제 journal 계약과 달랐다. 벡터 삭제가 journal transaction 안에서 이미 끝나는 경우를 원자적 삭제로 검증하고, 물리 정리 실패는 실제 raw 파일 삭제에 주입했다. 감사 실패는 접근 차단→startup replay 후 제외 완료를 검증한다. runtime 보호를 낮추어 시험을 통과시키지 않았다.

상세 환경/파일 hash는 [증거](evidence/v0.2-rag-retrieval/verification.json)를 따른다. 로컬 읽기 전용 진단의173.95ms 최대 관측은 15회·작은 문서·합성 질의 벡터 조건이며 S13 규모의 p95 보장으로 해석하지 않는다. 실제 도입 원본 DB는 읽기 전용 진단 외에는 재색인하지 않았고 추가 유료 API 호출은0회다.

## 재현 범위

- 호스트 Node24·pnpm 환경에서 `pnpm build`, `pnpm lint`, `pnpm test`, `pnpm db:validate`, `pnpm test:deployment`를 실행했다. 일부 HTTP 시험은 임시 loopback 포트 권한이 필요하다.
- Linux build/migration 이미지에서 `TOWNBASE_FILE_INDEX_TEST=1`·정확한 `postgres/townbase_d04_test`, `TOWNBASE_RAG_TEST=1`·정확한 `postgres/townbase_e02_test`를 사용했다. owner URL/runtime password 파일과 migration·runtime ACL 준비 후 각각 해당 spec을 실행했다. guard를 우회하거나 도입 DB를 테스트 DB로 사용하지 않는다.
- 권한 시험은 `deployment/test/runtime-role.integration.mjs`와 정확한 `postgres/townbase_pr34_rag_quality_test`를 사용했다. 일반 test:deployment에 DB 권한 시험이 포함된 것으로 설명하지 않는다.
- 로컬 replay 명령: 프로젝트 루트에서 `pnpm --filter @townbase/api exec ts-node --project tsconfig.json src/evaluation/retrieval-replay.ts /absolute/private-fixture.json /absolute/new-report.json`. 입력은 `{chunks: RagSource[], questions: [{question: string}]}`이며 최대8MiB·5000조각·120문항이다. 새 출력 파일만 허용한다. 해당 fixture의 자료 접근/소유/반출 권한은 실행자가 확보해야 한다. live 검색/모델 평가 명령이 아니다.

## 제한과 다음 확인

- 15문항 답변 점수9/30의 새 점수는 아직 없다. 실계정 질문 임베딩·답변 호출, 정답 근거 직접 제공 비교, OPS/SHOP 품질 재측정은 하지 않았다. 과거 query embedding을 보관하지 않아 당시 전체 후보를 복원하지 않았다.
- PDF의 원문 행/단위를 보존하는 개선이며 좌표로 병합 셀과 열을 재구성하는 표 파서는 구현하지 않았다. 긴 단일 행/표는 일부만 잘라 완전한 근거처럼 취급하지 않는다. 표 대응의 충분성은 실제 답변 시험에서 추가 확인한다.
- 한국어 어휘 후보는 초기 결정적 문자열 일치다. 형태소 분석·질문 분해·임베딩 large 전환을 완료했다고 주장하지 않는다. 실제 질의의 검색 누락은 trace와 필수 근거 완비율로 계속 점검한다.
- Q08의 원래 `invalid_grounded_response` 세부 원인, 부분 근거 답변, 동일 PDF 내부 충돌 표현은 묶음 B에 남아 있다. 이번 검색 개선만으로 이 오류가 해결됐다고 설명하지 않는다.
- 새 분할은 수동 색인 실행 시 적용되며 유료 임베딩이 발생한다. 운영자가 대상과 비용을 확인해 실행한다. 새 검색 코드는 기존 v2 색인에도 적용할 수 있다.

## 로컬 반영/전달

현재 도입 DB의 사전 백업을 `.townbase/maintenance/before-rag-quality-20261110.dump`(0600·git 제외)에 준비했다. 로컬 migration/API 교체 후 readyz HTTP200·database/schema/execution ready를 확인했다. 기존 행복주택 v2 색인27개 벡터는 그대로 보존했다. 새 검색은 현재 서버에 반영됐으며 새39개 분할은 다음 수동 색인 때 적용된다. 시험 전용 DB/네트워크/이미지 태그는 정리했다. 세부 사항은 증거 파일의 localDeployment 상태를 따른다. 문서 재색인과 모델/effort 변경은 이 배포에서 자동 실행하지 않는다. 커밋/푸시/main PR은 요약 승인 뒤 진행한다.

2026-11-10 사용자가 커밋/푸시/main PR 생성을 승인했다. 기존 미커밋 첫 사용 개선과 검색 개선은 별도 커밋으로 전달한다. 실제 답변 점수 재측정은 모든 개선이 끝난 뒤 사용자가 직접 수행하며 이번 전달 및 후속 구현에서 자동 실행하지 않는다.

## 변경과 업그레이드

새 migration은 첨부용 `20261108010000_private_attachments`와 최근 채팅 목록 인덱스용 `20261108020000_chat_navigation`이다. 첨부 migration은 Task/Attachment의 설치/소유 복합 FK·상태/결과·한도·작업당 단독 실행을 강제한다. 기존 migrations는 재작성하지 않았다. 새 테이블은 SELECT/INSERT/정리 DELETE와 열거된 상태/결과 열 UPDATE만 허용한다. 감사/세션은 보관 정리 DELETE만 추가한다. PUBLIC의 새 권한이나 다른 식별 열/REFERENCES/전체 UPDATE는 거절한다.

새 operations volume은 기존 documents/attachments와 분리한다. 업그레이드 전에 [수동 snapshot](../backup-and-restore.md)을 만들고 분리 master key와 최신 삭제 기록을 보존한다. `/readyz`는 operations 경로 쓰기와 파일 작업 단독 소유권도 확인한다. `/health`만 보고 실행 가능으로 판단하지 않는다. 소유권을 잃으면 새 작업을 거절하며 운영자가 원인을 확인한 뒤 단일 API를 재시작한다.

## 품질 조정과 실패 보존

처음의 raw0.45/top3평균0.40 단독 필터는 정확한 한국어 항목명이 있어도 거절하는 사례가 있었다. metadata 가산점과 분리된 기존 raw gate를 유지하면서, 두 단어 이상인 정확 항목 구절 또는 raw0.25 이상·질문 어휘75% 이상의 근거로 진입을 보완했다. 여러 절을 묻는 질문은 절별 근거를 확인한다. 정답표/질문 ID/특정 corpus 값은 제품 로직에 넣지 않는다. 진입 뒤에도 모델의 사실 판단·원문 인용·현재 접근 범위를 검증한다.

모델이 긴 UUID를 잘못 베끼는 실패는 현재 요청의 S1/S2 라벨을 실제 UUID에 엄격 매핑해 해결했다. 저장/조회는 실제 UUID를 유지한다. 문장이 떨어진 인용은 모든 문자가 원문의 순서 있는 정확 구절로 확인될 때만 여러 quote로 나눈다. 숫자/철자/문장부호/fuzzy 수정은 하지 않는다. 한 evidence 구절1,000자·claim당 인용10개·결과64KiB 상한과 출처 검사, 충돌 항목마다 다른 문서2개를 유지한다.

일부 출력은 필드명 변경/인용 개수 때문에 형식 검증에 실패했다. 최종 호출은 고정 strict JSON schema를 Responses text.format으로 전달한다. schema도 C의 보수적 입력 예산에 포함한다. 연결 검사는 일반 텍스트, 임베딩은 기존 고정 계약 그대로다. schema가 근거의 진실성을 보장하는 것은 아니므로 서버 인용/신원/버전 검증을 계속한다. [공식 API 안내](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)를 확인했다.

baseline·calibrated·candidate2·candidate3 실패/unknown 예약은 덮거나0원 처리하지 않는다. 최종 candidate4는 두 corpus 각각60개·3회이며 공개 합성 회귀다. 비공개/블라인드 검증·고객 문서 일반화·200문서/5,000 chunk 전체 규모 보장이 아니다. 실제 조건·분모·최종 수치는 [평가 결과](../evaluation/v0.2/final-2026-11-08.md)를 따른다.

- 브라우저: 관리자 로그인/세션 만료 복귀, 설정 저장, 실제 파일 등록→실행/색인→출처 답변, 새로고침 후 재조회, 첨부 요약/소유자 결과 재조회, 운영 pending 원문0을 확인했다. 공급자는 이 UI 시험만 합성 구현으로 교체했고 실제 Key는 입력하지 않았다. 화면 증거는 별도 보관한다.
- 복원1: snapshot T0 뒤 문서 삭제 T1→최신 별도 기록→빈 DB 복원. 로그인·첨부 결과 유지, 삭제 문서0·과거 답변 비노출을 인증 API로 확인했다.
- 복원2: 남길 문서/색인/답변이 있는 snapshot→다른 빈 DB+실제 runtime 이미지 복원. 잘못된 master key 거절, 정상 Key 복호화·원본 hash/크기/0600·다운로드·검색 가능 상태·대화/첨부 결과·이전 삭제 답변 차단·priceVersion=null을 확인했다. 내부 검색도 합성 query vector로 실제 제한 계정/신원 범위에서1건 반환했다. 새 외부 모델 호출은 하지 않았다.

직접 API·인증/전송 실패·암호 변조·DB/저장 장애·timeout·취소/재시작·관계/열 권한 시험은 실제 실행한 범위만 증거로 인정한다. 모든 공격·네트워크/디스크 장애에서 데이터 손실이 없다는 보장은 아니다. 운영 HTTPS 종료/인증서·외부 백업/DB/proxy 로그 만료는 설치자가 맡는다. native Linux x86_64 전용 장비의 확장 성능 시험과 공급자 최종 청구서 대조는 이 실행의 완료로 주장하지 않는다.

## 채팅 UI 최종 반영

사용자의 ChatGPT형 UI 요청에 따라 기본 화면은 대화/하단 입력창으로 구성하고, 주요 메뉴와 저장된 대화 목록은 기본 닫힌 햄버거 메뉴로 옮겼다. 설정은 모델/계정/실행/Gap/운영의 별도 페이지다. 대화 진입마다 서버에서 최신20개 메시지를 읽고 이전 기록을 추가 조회한다. 목록은 제목/시각 메타데이터만 반환한다. 일반 대화30일 보관과 현재 접근/출처 검사는 유지한다.

최근 정상 RAG 응답 최대3개 문맥은 사용자가 끌 수 있다. private 작업 목록/내용은 일반 RAG 대화와 분리하고, 첨부를 추가하면 별도 private 작업으로 연다. 토큰 실시간 스트리밍은 구현하지 않았으며 처리 상태와 실제 중지·결과 재조회를 제공한다. 중지는 늦은 결과 표시를 차단하지만 이미 전송된 요청의 과금 취소를 뜻하지 않는다.

별도 합성 브라우저 시험은 저장 대화 열기·후속 질문·새로고침·뒤로가기·Enter/Shift+Enter·출처 펼치기·중지·계정/모델 설정 분리를 확인했다. 610px 뷰포트에서 가로 넘침이 없었다. [채팅](evidence/v0.2-final/chat-final.jpg), [메뉴](evidence/v0.2-final/menu-final.jpg), [중지](evidence/v0.2-final/chat-stopped.jpg) 화면과 [복원 readback](evidence/v0.2-final/restore-runtime-readback.json)을 보존했다.

최종 재실행 중 로컬 포트 권한 제한으로 HTTP suite가 실패한 실행은 제품 실패와 구분했다. 권한을 적용한 첫 전체 실행에서도 기존 access.spec의 /auth/session 1건이 404였고, 단독17개·후속 전체533개·직전 HTTP suite를 묶은30개는 통과했다. 이 1회 비재현 오류의 근본 원인을 확인했다고 주장하지 않는다.

실행 집계와 로그 hash는 [verification.json](evidence/v0.2-final/verification.json)에 보존했다. 이번 작업의 임시 서버는 중지했고 실 Key의 임시 복사본을 삭제했다. 기존 프로젝트 Key와 다른 서비스는 변경하지 않았다.

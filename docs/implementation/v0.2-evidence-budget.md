## 진단

- 15문항 모두 근거 JSON이 7,641~7,999B로 8,000B 한도에 닿았다. 질문당 전체 입력 상한 계산값(`inputBound`, UTF-8 bytes+256)은 형식 포함 약 12.2K로, 기본 입력 한도 16,000에 약 3.8K가 남았다.
- Q13: 28쪽 조각이 전달됐지만 구간이 `■ 갱신계약자격` 제목에서 끝났다. 바로 다음 줄인 "\* 다만, 아래 경우는 제외"와 "- 청년계층의 경우 19세이상 39세이하"가 빠졌다.
- Q09: 10쪽 조각 구간이 109글자 뒤에서 시작해, 그 앞의 `1순위`·`2순위` 행이 빠졌다.
- 색인 v4는 조각을 약 2KB로 줄였다. 그래서 첫 근거는 조각 전체(약 2KB)를 보내지만, 나머지 4개 출처는 약 1KB 구간만 받고 경계에서 잘렸다.
- Q14(9~10쪽 소득표 미선택), Q03(사전 판정), Q07(형식 규칙)은 예산과 다른 원인이다. 이번 변경 범위가 아니다.

## 변경

- `ragEvidenceBudget`(`apps/api/src/rag/rag-policy.ts`): 질문마다 실제 지침·질문·Agent 설정·대화 이력·응답 형식을 뺀 입력 한도의 남은 크기를 근거 예산으로 쓴다. 하한은 기존 8,000B, 상한은 12,000B(`RAG_EVIDENCE_MAX_BYTES`)다.
- 하한을 두는 이유: 이력이 길어 여유가 8,000B보다 작으면 이전과 같은 8KB로 선택하고, 초과하면 이전처럼 `input_limit_exceeded`로 거절한다. 입력을 맞추려고 근거를 몰래 줄이지 않는다.
- 근거 예산은 남은 크기와 정확히 같다. 이 크기의 근거는 입력 검사를 통과하고, 1B만 넘어도 거절된다(시험으로 확인).
- `selectSources`와 `growWindows`가 예산을 인자로 받는다. RAG 질문(`rag.service.ts`)만 계산된 예산을 넘긴다. 첨부 작업과 로컬 검색 재현 도구는 기존 8KB를 그대로 쓴다.
- 근거 최대 5개, 첫 근거 전체 전송, 처음 구간 1,000B/1,800B, 어휘 상위 후보 자리, 인용 검증, 전송·권한 검사는 바뀌지 않았다.
- 비용: 기본 설정에서 질문당 입력이 최대 약 4KB 늘어난다. 2026-11-11 관측으로는 한국어 근거 3~4B가 약 1토큰이므로 약 1~1.3K토큰이고, `gpt-6-luna` 일반 입력 단가로 질문당 약 US$0.0001~0.00013이다. 바이트 기준 상한 계산은 실제 토큰보다 보수적이다.

## 실제 데이터 재현 (모델 호출 없음)

위 15문항에 저장된 근거 5개를 후보로 다시 선택했다. 이 재현은 실제 Agent 설정·질문, 입력 한도 16,000으로 실행했다. 저장된 근거만 후보로 쓰므로 순위 밖 후보가 끼어드는 경우는 재현하지 않는다.

- 질문당 예산은 11,739~11,883B였고, 실제 사용은 9,127~11,417B다.
- Q13: "\* 다만, 아래 경우는 제외 / - 청년계층의 경우 19세이상 39세이하"가 전달된다(이전 누락).
- Q09: `1순위` 행이 전달된다(이전 누락).
- 나머지 문항은 이전에 전달되던 확인 문자열이 모두 그대로 전달된다. 선택된 출처의 수와 순서는 15문항 모두 이전과 같다.
- Q14의 소득표, Q08의 4인 140% 표 행(`12,323,083원`)은 선택된 5개 조각에 없어 예산과 무관하게 그대로다.

재현은 근거 전달 여부만 확인한 것이며 모델 답변의 정확도를 뜻하지 않는다.

## 검증

- 새 시험(`rag-policy.spec.ts` "R07 evidence budget", `rag-evidence-budget.spec.ts`):
  - 짧은 설정은 상한 12,000B, 긴 설정은 8,000B 초과·상한 미만인지
  - 8KB에서 잘리던 예외 줄이 같은 출처 선택으로 전달되고, 프롬프트가 입력 한도를 넘지 않는지
  - 예산 크기의 근거는 통과하고 1B 초과는 `input_limit_exceeded`인지
  - 이력이 길거나 한도가 4,096일 때 8KB 하한을 유지하는지
  - `RagService`가 실제 답변 호출에 8KB를 넘는 근거와 예외 줄을 넣는지
- 수정 전 코드에서 정책 시험은 새 인자·함수가 없어 실패하고, 서비스 시험은 근거 7,986B로 실패함을 확인했다.
- `pnpm lint`, `pnpm build`, `pnpm test`(730개 통과, opt-in DB suite 334개 건너뜀), `pnpm test:deployment`(53개) 통과.
- RAG 실 DB suite(`TOWNBASE_RAG_TEST`)와 실계정 모델 호출은 실행하지 않았다.

## 남은 확인

- 병합 후 API를 다시 빌드한다. 재처리·재색인은 필요 없다. 이후 Q13·Q09를 중심으로 재측정하고, 확인용으로 다른 문항도 함께 묻는다.
- Q03(사전 판정 기준), Q07(답변 가능과 추가 확인 항목의 형식 규칙), Q14(소득표 미선택)는 별도로 다룬다.

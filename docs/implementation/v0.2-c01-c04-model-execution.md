## 제공 범위와 API

- 답변 `gpt-6-luna` 기본·`gpt-6.1-sol` 선택, 초기 추론 low. 읽기 전용 임베딩 `text-embedding-3-small`/1536. 임의 모델·provider·endpoint·임베딩 차원·자동 모델 fallback을 허용하지 않는다.
- 기존 Key/전송 API에 모델·입출력 한도·운영자 명시 예산/가격표 확인을 추가했다. 변경은 기존 세션 폐기 잠금·현재 비밀번호 재확인·시도 제한·설치 검사와 성공 감사의 원자성을 유지한다. 같은 값은 재인증하지만 변경 감사/updatedAt를 추가하지 않는다.
- `GET/PUT /settings/model-integration/execution`, `POST /settings/model-integration/checks/answer|embedding`, `GET /settings/model-integration/calls/:requestId`. 설정/check 본문은 정확한 필드 목록만 허용한다. Origin·JSON·기본 인증·no-store는 기존과 같다.
- 연결 검사는 서버 고정 합성 문장만 사용한다. Key 저장은 성공 검사가 아니며 실제 네트워크에 성공해야 verified다. 현재 Key tag·설정 fingerprint가 다른 과거 검사는 재사용하지 않는다. 비용 상태 API와 호출 결과 메타데이터를 DB에서 재조회한다.
- 일반 호출은 내부 ModelExecutionService가 제공한다. 이 서비스만 후속 D/E/F에서 사용한다. 현재 운영 채팅·파일 등록·첨부·기존 MCP/Connector를 활성화하지 않았고 설정 웹도 아직 없다. C 비용 기록에 원문/답변/첨부/Key를 저장하지 않는다. 실제 답변·작업 결과의 소유자별 저장은 E/F 책임이다.

## 호출·접근·전송 경계

1. 최신 세션의 설치/관리자/workspace를 확인한다. 짧은 인증 transaction 안에서 설치 행을 잠가 설정과 비용 예약을 직렬화한다. 일반 내부 호출도 폐기 잠금 경계를 공유하며 작업 중 만료면 예약까지 취소한다.
2. 같은 설치의 기존 요청 ID를 먼저 확인한다. 같은 ID·내용은 기존 상태를 반환하며, 다른 입력이나 소유자라면 충돌/거절한다. 모델/Key 변경이 기존 요청을 재전송할 근거가 되지 않는다.
3. 지원 모델/가격표 확인·예산·해당 용도 전송 허용·본문/파일명 기본 비밀 검사·활성 Key·고정 endpoint·입력 한도를 검사한다. 거절 시 외부 요청은0건이다. Key는 인증된 봉투에서만 복호화한다.
4. 비용과 호출 상태를 실제 저장하고 transaction을 commit한 뒤 native fetch를 호출한다. 인증/설치 잠금을 잡은 채90초 동안 원격 응답을 기다리지 않는다. 리다이렉트·재시도·도구·백그라운드·원격 file-search/vector-store를 사용하지 않는다.
5. API 호출과 body 읽기에 abort signal을 적용하고 응답 크기는1 MiB로 제한한다. 응답 model·상태·usage·벡터 개수/index/유한 값/차원을 검사한다. 공급자 원문 오류·헤더·Key/본문을 로그/응답에 복사하지 않는다. 오류는 고정 코드로 남긴다.

입력 제한은 정확한 tokenizer 대신 UTF-8 bytes+256 framing의 보수적 상한이다. 기존 공백 tokenizer를 API tokens로 오인하지 않는다. 설정 한도보다 크면 명시 거절하고 자르지 않는다. 한국어의 정상 긴 입력도 과도하게 거절할 수 있다는 제한을 안내했다. 임베딩은 같은 상한8,192, 전체 답변 입력16,000·추론 포함 출력4,096 이내다. E/F는 각 질문/근거/대화/첨부 예산을 추가해야 한다.

## 저장·권한·비용 계약

`ModelExecutionSettings`와 `ModelCall`을 추가했다. 설치 FK·복합 소유자 FK·요청 ID unique·허용 값/한도/금액/상태 CHECK는 migration에 둔다. Prisma schema만의 db push로 대체하지 않는다. 준비 상태 검사는 두 테이블을 읽는다. runtime에는 SELECT/INSERT와 필요한 설정/정산 열 UPDATE만 추가했다. 호출 ID·소유자·용도·모델·예약액·시각 등은 UPDATE하지 못하고 두 테이블을 DELETE하지 못한다. PUBLIC 우회 권한 검사도 같은 목록을 반영한다.

- 예산과 가격표 확인은 처음에는 null로 유료 호출을 차단한다. $20 개발 기준을 자동 입력하지 않는다. 가격 버전은 `openai-global-standard-2026-10-26`이며 일반 글로벌 Standard의 입력/캐시 읽기/30분·12시간 쓰기/출력 단가를 고정한다. 변경은 명시적 제품 변경/검증이다.
- 금액은 nanoUSD 정수다. 공급자 usage의 캐시 읽기/쓰기/일반 입력은 중복 없이 구분한다. 추론은 출력의 부분집합으로 검증하고 두 번 더하지 않는다. 정산은 설치의 같은 잠금 경계에서 수행해 조회 사이에 정산/예약이 엇갈려 한도를 빠져나가지 못하도록 한다. 화면용 합계는 일관된 DB snapshot으로 읽는다.
- 예약은 설정된 입력 상한과 최대 출력, 가능한 최고 캐시 쓰기 단가로 계산한다. 임베딩/답변 비용을 합산해 동시에 들어오는 요청도 한도를 넘지 못한다. 80% 경고·100% 신규 차단·예약 추가 시 초과 차단이다. 현재 달의 정산액과 모든 달의 미확인 예약을 합산한다. 월은 UTC 달력 기준이다.
- 답변 동시1개·최근60초10회·호출90초. ID 중복 확인은 새 요청의 한도/전송보다 앞서므로 설정 변경/재시작 후에도 저장된 상태를 재조회할 수 있다.
- 전송 전에 admission deadline이 지난 경우는 `not_sent`·0원으로 확정한다. 전송 후 HTTP 실패/timeout/응답·usage 파싱 실패는 `unknown`·청구액 null로 예약을 유지한다. incomplete에 확인된 usage가 있으면 비용을 정산하되 성공으로 표시하지 않는다.
- 응답 후 DB 정산이 실패하면 dispatching/예약을 남긴다. 같은 ID는 재전송하지 않는다. deadline 경과는 조회에서 unknown으로 보이고 다음 호출 입장 시 DB 상태도 정리한다. 오래된 unknown의 비용을 자동으로 해제하지 않는다. 공급자 청구 대조와 수동 정산/해제 기능은 별도 검토 대상이다.
- 원문/답변은 저장하지 않고 fingerprint와 비용 메타데이터만 남긴다. 호출 기록90일 정리·전체 운영 백업/복구는 후속 I의 보관/비용 이월 계약과 함께 연결해야 한다. 미확인 비용을 보관 만료로0원 처리하면 안 된다.

## 재현·범위

일반 검증은 Node24에서 다음 명령을 각각 실행한다.

```sh
pnpm build
pnpm lint
pnpm test
pnpm test:deployment
```

업그레이드 통합 시나리오는 일반 test:deployment에 포함되지 않는다. migration 이미지에서 `TOWNBASE_FILE_PREFLIGHT_TEST=1`과 정확한 postgres/townbase_d01_pr41_preflight_test의 새 빈 DB, DB 소유자·runtime secret 환경으로 `node --test deployment/test/file-extraction-preflight.integration.mjs`를 명시 실행한다. 시험은 구버전 schema·합성 데이터·migration 이력을 생성하며 기존 DB를 자동 초기화하지 않는다. public schema에 테이블·뷰·sequence 등 기존 관계가 있으면 시작을 거절한다. 빈 `_prisma_migrations` 테이블이나 이력만 남은 상태도 포함한다. 반복하려면 운영 DB와 구분한 이 전용 시험 DB만 운영자가 명시적으로 재생성해 같은 이름의 빈 DB를 준비해야 한다.

기존 D01 DB suite의 guard와 실행 조건은 [이전 대응 기록](v0.2-d01-review-response.md)을 따른다. 로컬 증거는 /tmp/townbase-pr41-{build,lint,api,control,deployment,preflight-unit,integration,d01-db,image,runtime}.log와 /tmp/townbase-pr41-real-child.cjs에 있다. 신규 통합 runner는 /tmp/townbase-v02-b04/pr41-preflight-integration.mjs다.

사용자 요청에 따라 검증 요약 후 커밋·푸시·PR 댓글로 전달한다. 공개 업로드/임베딩·재시작 파일 orphan 복구는 이번 범위에 추가하지 않는다.


Compose 재현 예시(프로젝트 이름/설정 파일은 실제 시험 설치에 맞춤): PostgreSQL이 실행 중이고 위 전용 DB가 새 빈 상태이며 최신 migration 이미지가 빌드돼 있어야 한다.

```sh
docker compose --env-file .townbase/compose.env -p my-townbase run --rm --no-deps -e TOWNBASE_RUNTIME_PROFILE=self_hosted -e POSTGRES_DB=townbase_d01_pr41_preflight_test -e TOWNBASE_FILE_PREFLIGHT_TEST=1 --entrypoint node migration --test deployment/test/file-extraction-preflight.integration.mjs
```


## 추가 리뷰 6건 대응 (2026-10-29)

- 업그레이드 성공 전후 FileVersion 전체 행을 비교한다. 추출 JSON·메타데이터·시간 열도 보존 검증에 포함한다. 비교 기준은 합성 자료를 명시적으로 복구한 직후다.
- 시험의 빈 DB guard는 public의 테이블·partitioned table·뷰·materialized view·foreign table·sequence를 읽기 전용으로 검사한다. 이력 테이블만 존재하거나 일부 schema만 남은 DB도 거절한다. 실제 DB에서 빈/행 있는 migration 이력 테이블과 부분 테이블을 각각 확인하며 시험이 직접 만든 객체만 정리한다.
- 사전 검사 CTE는 NOT MATERIALIZED로 두 참조에 펼친다. 개수 집계와 정렬된 최대20개 ID 조회를 같은 SQL snapshot에서 수행하며 전체 불일치 ID 목록을 임시 저장하지 않는다. 전체 개수 계산을 위한 스캔은 여전히 필요하다. 대규모 성능 개선 수치는 측정하지 않았다.
- 실제 업그레이드 시나리오에 비호환25건을 넣어 전체 개수25·정렬된 표본20·나머지 ID 비노출을 검사한다.
- tagged/unsafe 쿼리 호출을 모두 기록하고 새 설치는 테이블 존재 검사1회만 수행하는지 확인한다.
- 파이프는 종료 대기 중이 아니라 close 미확인으로1초 후 격리할 때 닫는다고 배포 안내를 수정했다. 일반 배포 시험에 사전 검사·guard 단위6개가 포함되고 실 DB 시나리오는 별도임을 명시했다.


검증: 일반 `pnpm test:deployment` 24개·실 DB 업그레이드 시나리오1개 통과(총25개). 이번 시나리오에서 새 설치/빈 이력 테이블/이력 행만 존재/부분 테이블 차단·25건 진단·전체 행 보존을 함께 확인했다. 완료한 DB 재진입은 예상대로 시작 전에 실패했으며 전체 FileVersion와 migration 이력의 전후 snapshot이 같았다(추가 수동 확인,25개에 중복 합산하지 않음). Node 문법·`git diff --check`도 통과했다. TS/API/파서·schema·적용 SQL은 바꾸지 않아 해당 전체 suite나 이미지를 다시 빌드하지 않았다.

이전 시험 환경의 임시 secret 파일이 없어 기존 PostgreSQL을 시작할 수 없었다. 기존 volume/DB를 변경하지 않고 별도 `townbase-pr41-followup` 네트워크·새 PostgreSQL 임시 데이터 영역에서 정확한 guard DB 이름으로 실행했다. 기존 migration 이미지의 빌드 산출물에 최신 deployment 소스를 읽기 전용으로 마운트했다. 로그는 `/tmp/townbase-pr41-followup-{deployment,integration,reentry}.log`, 재진입 확인 스크립트는 `/tmp/townbase-pr41-followup-reentry.py`다. 대규모 데이터의 성능 측정이나 실계정 유료 호출은 수행하지 않았다.

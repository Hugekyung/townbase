## 관련 경계 검증

- 파일을 기다리는 동안 DB 잠금이 없음을 일반 내부 실행과 합성 연결 검사 양쪽에서 검증한다. 준비를 멈춘 상태에서도 로그아웃이 먼저 성공하고, 준비 재개 후 새 입장은 거절되며 예약/외부 호출은0건이다.
- 준비 사이에 교체된 Key와 변경된 전송 정책을 실제 최신 행에서 읽는다. 거절 시에도 준비된 master를 폐기한다. master 자체가 없어져도 기존 요청의 상태 재조회/중복 반환에는 파일을 읽지 않는다.
- 예산 미설정·전송 미허용은 파일 접근 전에 거절한다. 준비 후에도 같은 검사를 되풀이해 초기 결과로 허용을 고정하지 않는다. API/내부 입력과 파일명 목록은 비동기 처리 전에 복사해 digest와 검사/전송 내용이 달라지지 않도록 한다.
- 입력 초과·출력 초과는 답변/임베딩 각각 검사한다. 오류의 실제 DB 행·정산액 null·미확인 예약·동일 ID 재요청·결과 미반환을 검증한다. 계산 비용만 예약액보다 큰 독립 조건과 정확한 경계 허용은 단위 시험으로 따로 확인한다.
- 종전 암호문 nonce/tag/봉투와 plaintext Buffer 정리·master 파일 형식/권한·Key 저장/감사 원자성을 유지한다. 운영 프로필의 fake embedding/다른 모델/임의 endpoint 대체 경로는 추가하지 않는다.

실제 유료 호출은 이번 리뷰 보완에서 재실행하지 않는다. 기존3회 성공 기록과 이번 합성/DB 검증을 합산하지 않는다. 실제 공급자 청구를 앱에서 확정/취소할 수 있는 것으로 설명하지 않으며 사용량 이상도 과거 예약을0원 처리하지 않는다.

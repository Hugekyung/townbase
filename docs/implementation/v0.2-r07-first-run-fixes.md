## 첫 재평가 관측 (2026-11-11 03:10~03:23 UTC)

- 15문항을 한 대화에서 연속으로 질문해 이전 3개 결과가 문맥으로 함께 들어갔다. 채점 기준(질문마다 새 대화)과 조건이 다르다.

## 인용 검증 변경

- `locateExcerpts`는 먼저 정확 일치를 찾는다. 없으면 **공백만** 다른 일치를 허용한다. 공백이 아닌 모든 글자·숫자·문장부호는 순서대로 연속해 정확히 같아야 한다.
- ASCII 영문자·숫자 사이의 공백 유무는 바뀔 수 없다. `3\n4`를 `34`로, `34`를 `3 4`로 인용하면 거절한다.
- 저장하는 인용은 모델이 쓴 문자열이 아니라 근거의 정확한 원문 구간이다. 저장 재조회는 기존처럼 정확 일치로 다시 검증한다. 출처 위치·충돌 양쪽 판정도 실제 구간 위치를 쓴다.
- 떨어진 문장을 이은 인용은 기존 규칙(2~5조각, 순서 유지)을 유지하고, 각 조각에 같은 공백 규칙을 적용한다. 조각마다 정확·공백 허용 일치 중 끝이 가장 이른 것을 고른다. 이 선택은 다음 조각의 자리를 가장 넓게 남기므로, 다른 조합이면 통과할 인용을 거절하지 않는다.
- 같은 검증 함수를 첨부(v1) 결과도 사용한다. 첨부 지침·schema·직렬화 hash는 바뀌지 않았다.
- 문장부호 정규화(따옴표·가운뎃점·글머리표 변형)나 유사 문자열 보정은 하지 않는다. 지침 문구도 바꾸지 않았다.

## 진단 코드

공개 오류는 `invalid_grounded_response`를 유지한다. 인용 실패의 내부 분기를 셋으로 나눈다.

| 코드 | 의미 |
| --- | --- |
| `TOWNBASE_RAG_GROUNDING_QUOTE_MISMATCH` | 글자·숫자가 근거에 없음(내용 차이 또는 순서 차이) |
| `TOWNBASE_RAG_GROUNDING_QUOTE_PUNCTUATION` | 글자·숫자는 같고 문장부호·기호만 다름 |
| `TOWNBASE_RAG_GROUNDING_QUOTE_SPACING` | 공백만 다르지만 영문자·숫자 사이 경계가 바뀜 |

이 분류는 진단 전용이다. 약한 비교로 인용을 통과시키지 않는다. 과거 로그의 `QUOTE_MISMATCH`는 당시 공백 차이까지 포함한 의미이므로 새 로그와 합산하지 않는다.

## 채팅 화면

- 출처 위치는 줄마다 저장된다. 화면은 같은 위치를 순서대로 한 번만 표시한다(`3쪽 · 4쪽`). 저장 형식은 바뀌지 않았다.
- 대화 스크롤 영역(`.thread-scroll`)에 `position: relative`를 추가했다. 화면에 보이지 않는 접근성 라벨이 스크롤 영역 밖에 배치되어 입력창 아래로 빈 페이지 스크롤이 생기던 문제다. 실제 stylesheet와 같은 DOM 중첩의 정적 재현에서 문서 높이가 2718px에서 768px(창 높이)로 줄었다. 로그인한 실제 앱 화면에서는 확인하지 않았다.

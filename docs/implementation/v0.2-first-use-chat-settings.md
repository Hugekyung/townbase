# v0.2 첫 사용 개선 — 채팅 설정·사용량·고정 메뉴

2026-11-10. 기준 main `63633620049bcb36d1a9179c8620d653d0795c97`, 별도 작업 브랜치 `codex/chat-model-usage-sidebar`. 사용자가 첫 사용 중 요청한 개선과 직전 연결 상태 표시 오류를 함께 반영한다. 로컬 설치에 적용했으며 커밋·푸시·PR은 이번 검증 요약 뒤 승인 대상이다.

## 동작

- 로그인/대화 기록 조회와 모델 실행은 별개다. 새 문서 기반 답변에는 답변·임베딩 Key 활성화, 유효한 예산/가격표 확인, RAG 전송 허용과 기본 Agent/검색할 문서가 필요하다. 첨부 답변에는 답변 Key와 첨부 전송 허용이 필요하며, 혼합 검색에는 임베딩 Key와 RAG 전송 허용도 필요하다. Key가 없을 때 다른 계정·모델·가짜 답변으로 대체하지 않는다. 화면은 미설정 안내와 설정 이동을 제공한다.
- 입력창의 전송 버튼 왼쪽에서 지원 답변 모델과 추론 강도를 선택한다. 설치 기본값으로 시작하고 다음 전송에 적용한다. 다른 채팅·설치 기본 설정은 바꾸지 않는다. 미전송 선택은 편집 상태이며, 전송한 선택은 RagTurn/AttachmentTask.modelOptions에 실제 저장하고 별도 GET으로 재조회한다. 채팅을 다시 열면 최신 메시지의 선택을 복원한다. 과거 메시지는 바꾸지 않고 과거 NULL의 추론 강도를 소급 추정하지 않는다.
- modelOptions는 answerModel/reasoning 두 필드만 허용한다. 기존 지원 Luna/Sol 조합만 허용하고 임베딩은 small/1536 고정이다. C의 인증/전송/Key/설치 예산·가격·입출력 제한을 그대로 적용하고, 선택한 모델 단가로 비용을 예약한다. 변경 옵션도 중복 요청 fingerprint에 포함한다. 실행 중 기본 설정이 변경되면 기존 digest 경계에서 실패한다.
- 설정→API 사용량은 인증된 GET /settings/model-integration/usage와 기존 execution 예산 조회를 사용한다. UTC 현재 달의 설치·현재 관리자 호출을 모델/용도/상태·일별로 집계한다. 입력·캐시·출력·추론 토큰, usage 확인 호출 수와 추정 비용을 구분한다. 추론 토큰은 출력의 부분집합으로 중복 합산하지 않는다. 월 예산의 미확정 예약은 이전 달 이월을 포함하며 달별 호출 집계와 구분한다. OpenAI 계정 전체 사용량·최종 청구서가 아니다. Key·질문·답변 원문을 반환하지 않는다.
- 900px 이상 화면에서 메뉴를 펼치면 본문 옆에 고정된다. 새 채팅·설정 이동으로 자동 닫지 않으며 접기 전까지 유지한다. 열림 선택은 로컬 UI 설정으로 저장한다. 작은 화면은 배경/키보드 포커스 보호가 있는 모달 메뉴로 유지하고 이동 시 닫는다.

## 연결 상태 오류와 반복 끊김

기존 /readyz는 DB/스키마/저장소가 정상이어도 실행 소유권이 사라지면503을 반환했지만, 화면은3개 항목만 표시했다. execution 상태를 응답하고 관리자 설정/문서 처리·채팅 서비스도 화면에 표시한다. HTTP503 또는 실행 unavailable에서는 로그인·채팅 진입을 계속 차단하며 정상처럼 표시하지 않는다.

Prisma6.19.3의 전용 잠금 연결에서 max_idle_connection_lifetime=2를 지정한 비교 진단은 주기적으로 조회해도 약2초 뒤 PID 교체와 잠금 소실을 재현했다. 같은 조건의0 설정 연결은 유지됐다. fileLockConnectionUrl은 session advisory lock 전용 클라이언트에만 connection_limit=1·max_idle_connection_lifetime=0·max_connection_lifetime=0을 적용한다. 일반 DB 풀/질의 timeout은 바꾸지 않는다. 실제 소유권 상실의 차단·중단·운영자 재시작 경계는 유지한다. 자동으로 새 소유권을 재취득해 작업을 이어가지 않는다.

## 저장·로컬 적용

후속 migration `20261110000000_chat_model_options`는 두 결과 테이블에 nullable JSONB 열과 좁은 CHECK만 추가한다. 모델/추론 조합·형식·추가 키를 검사한다. 기본값/과거 데이터 backfill·기존 migration 수정·새 UPDATE 권한은 없다. 런타임 INSERT로 접수 시 확정하고 이후 선택 metadata는 불변이다.

`townbase-local` DB를 보호된 `.townbase/maintenance/before-chat-options-20261110.dump`에 먼저 보관한 뒤 API 중지→migration→API 재생성을 진행했다. 이 파일은 DB 전용 사본이며 원본/별도 master key까지 묶은 전체 복구 백업으로 설명하지 않는다. 적용 전후 관리자1·지속 파일0·대화0·모델 호출0을 확인했다. 기존 계정·volume·Key 파일을 바꾸지 않았다. 실제 개인 화면 검증은 전송 없이 수행했으며 개인정보가 포함된 스크린샷을 저장소에 넣지 않는다.

## Key 저장 뒤 초기 설정 안내 보완

실제 설치에서 답변/임베딩 Key는 정상 저장·활성화됐지만 월 예산·가격표·전송 정책·기본 Agent가 미설정이었다. not_checked는 로딩이 아닌 유료 연결 검사 미실행 상태다. Key 저장 성공과 채팅 실행 준비 완료를 혼동한 안내를 바로잡았다. 실제 Key의 공급자 유효성을 새로 시험한 것으로 표시하지 않는다.

Key 변경 후 마스킹된 snapshot을 즉시 재조회한다. 저장 성공/후속 조회 실패를 구분하고, 원문 입력은 성공·실패 모두 지운다. 모델 설정은 전체 문서 페이지 조회와 독립적으로 표시하고 읽기 실패에는 재확인 버튼을 제공한다. 정상 재조회 중 다른 설정 폼을 불필요하게 초기화하지 않는다. 설정/채팅은 같은 modelSetupSteps 판정을 사용하며 현재 남은 항목과 이동 버튼을 표시한다. 비용 한도·가격표 확인·외부 전송 허용·Agent를 자동 설정하지 않는다.

웹 build/lint·API625개(기본 opt-in329개 skip), 그 부분집합인 설정/채팅9개를 통과했다. 기존 DB29/권한82는 이번 UI-only 수정 뒤 재실행한 것으로 합산하지 않는다. 실제 관리자 브라우저에서 두 Key 완료, 4개 미설정 항목, 읽기 로딩 해제와 채팅→설정 복귀를 확인했다. 추가 유료 호출0회. 로컬 반영 완료·커밋/푸시/PR 승인 전이며 [후속 검증](evidence/v0.2-first-use-chat/key-setup.json)을 따른다.

비활성 버튼의 전역/설정 화면 두 CSS 규칙에서 cursor:wait를 default로 수정했다. 로컬 반영·웹 build 통과, 실제 문서 관리의 disabled 등록 실행 버튼에서 computed cursor=default를 확인했다. 이 CSS-only 변경에 새 시험을 추가하거나 이전 전체 시험을 재실행한 것으로 표시하지 않는다. [검증](evidence/v0.2-first-use-chat/disabled-cursor.json)을 따른다.

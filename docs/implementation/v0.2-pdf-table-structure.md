# v0.2 PDF 표 구조 복원 — R04-b

2026-11-11. `codex/v02-table-structure`의 로컬 구현·검증 기록이다. [계획](v0.2-rag-quality-improvement-plan.md) §7 R04의 2·3항(표 머리글·단위·병합 셀 연결, 필요한 파서 보완)을 구현했다. 사용자가 좌표 기반 표 복원까지 진행하기로 결정했다. 실제 모델 답변 품질 재측정(R07)과 도입 문서 재처리·재색인은 포함하지 않는다. 커밋·푸시·PR은 사용자 승인 전에는 하지 않는다.

## 착수 시 측정 (도입 DB 읽기 전용)

행복주택 공고(32쪽) 원본과 추출문을 읽기 전용 transaction과 파일 복사로 가져와 로컬에서만 재현했다. DB·문서 변경과 모델 호출은 없었다. 원본 SHA-256은 저장값과 일치했다(`bb8a33e0…a55d`). 복사본은 검증 후 scratchpad에서 삭제했다.

| 발견 | 내용 |
| --- | --- |
| v3 분할의 위치 정보 과다 | `file-index-d04-v3`은 줄마다 위치 항목을 만든다. 모델 입력에 이 목록이 그대로 들어가 39개 조각 중 12개가 혼자서도 8KB 근거 예산을 넘었다. 3쪽 표 조각은 본문 2.2KB·위치 9.6KB였다. 후보가 하나뿐이면 `evidence_limit_exceeded`, 여러 개면 조용히 예산 탈락이었다. 도입 설치는 아직 v2 색인이라 드러나지 않았다. |
| 1,800바이트 구간 절단 | 예산이 남아도 조각마다 1,800바이트 구간만 보내 Q08의 `140%` 행과 15쪽 소득표가 빠졌다. |
| 표 연결 부재 | 머리글이 여러 줄로 흩어지고 행 값은 공백으로만 이어졌다. 병합 셀 행은 상위 조건과 연결이 없었다. |

## 표 복원 (파서)

`apps/api/src/files/pdf-table.ts`의 순수 함수와 `file-parser.ts`의 PDF 경로로 구현했다. pdf.js 6.4.299의 operator list와 텍스트 좌표만 사용하며 OCR·이미지 분석은 없다.

1. **괘선:** CTM(save/restore/transform)을 추적해 stroke 경로의 수평·수직 변과 두께 2.5pt 이하의 채운 사각형을 괘선으로 쓴다. 배경 채움·clip 경로는 무시하고, 알 수 없는 경로 연산은 표 복원을 중단한다. 곡선 뒤 열린 경로가 없는 직선도 좌표를 소비해 이후 경로 해석이 어긋나지 않는다. 점선은 경로 기하가 실선이므로 그대로 인식된다.
2. **격자·병합 셀:** 교차하는 괘선 연결 요소마다 격자를 만들고, 경계 괘선이 없는 칸을 병합한다. 병합 영역이 직사각형이 아니면 복원하지 않는다.
3. **텍스트 배치:** 항목을 칸에 배치한다. 한 텍스트 run이 여러 칸을 가로지르면 단어별 추정 위치가 경계에서 3pt 이상 떨어져 각 칸에 들어가고 가로지른 모든 칸에 단어가 있을 때만 나눈다. 표 가장자리에 걸친 텍스트와, 기준선이 수평이 아닌 회전·반전 텍스트가 표 영역(원점 주변 폭+높이 범위)에 닿는 경우도 복원 중단 사유다. 기울임(shear)만 있는 텍스트는 수평으로 본다.
4. **머리글:** 숫자형 칸이 절반 이상인 첫 행을 데이터 시작으로 보고, 그 위에서 아래로 걸쳐 내려오는 머리글 칸의 끝 행까지 머리글을 확장한다(예: `100% 110%` 같은 숫자형 머리글 행). 머리글을 정할 수 없으면 행마다 칸만 `|`로 구분하며, 세로 병합 칸은 이 경우에도 걸친 모든 행에 반복한다.
5. **출력:** 표 위치에 행 단위 한 줄씩 넣는다. 각 값에 전체 머리글 경로를 붙이고, 같은 상위 머리글 아래 이웃 열은 `상위 — 하위: 값, 하위: 값`으로 묶는다. 상위 머리글의 단위(예: 천원)가 모든 값에 붙는다. 병합된 행 칸은 해당하는 모든 행에 반복된다. 표 밖 텍스트는 원래 순서를 유지한다.

예: `공급 형별 (전용): 18 | 공급 대상: 청년계층 (소득有) | … | 임대조건 > 임대보증금(천원) — 계 (100%): 22,302, 계약금 (20%): 4,460, 잔금 (80%): 17,842 | 임대조건 — 월 임대료 (원): 92,800 | …`

- **추측 금지:** 위 조건 중 하나라도 불확실하면 그 표는 기존 텍스트 그대로 둔다. 복원 실패·operator list 오류도 기존 텍스트로 처리한다.
- **한도:** 표 복원으로 늘어난 페이지가 추출 상한(30만 code points)을 넘으면 그 페이지는 기존 텍스트를 쓴다. 기존 20MiB·30초·자원 상한과 추출 계약(PDF 위치는 `page`만)은 그대로이며 migration이 없다.
- **버전:** 추출 설정은 `file-extraction-d03-v2`다. 기존 추출문은 자동으로 바뀌지 않으며 명시적 재처리(`POST /files/:id/reprocess`)와 색인(`POST /files/:id/index`, 유료 임베딩) 후에 적용된다. 색인 설정(`file-index-d04-v3`)과 분할 규칙은 바뀌지 않았다. 새 추출문은 digest가 달라 이전 벡터를 재사용하지 않는다.
- 첨부도 같은 파서를 쓰므로 표 복원이 적용된다. 첨부의 보관·격리 규칙은 그대로다.

## 근거 전달 (RAG 정책)

- **위치 압축:** 모델에 보내는 `locations`는 보낸 구간에 해당하는 서로 다른 위치(쪽·문단·줄)만 담는다. 저장 출처는 전체 위치를 유지해 재조회·인용·같은 문서 충돌 판정이 그대로다.
- **상위 출처 전체 전달:** 1순위 출처는 단독으로 예산에 들어가면 구간을 자르지 않고 통째로 보낸다. 표 조각이 어휘상 동점인 다른 행으로 잘리지 않게 하려는 것이다.
- **구간 확장:** 나머지 출처는 기존 1,800바이트 구간으로 시작해, 남은 8KB 예산 안에서 출처마다 한 단위씩 번갈아 넓힌다. 예산 판정은 선택 때와 같은 prompt JSON이다.

## 한계

- 괘선이 있는 표만 복원한다. 괘선 없는 표, 회전 텍스트가 닿은 표, 이미지·스캔 표는 기존 텍스트 그대로다.
- 데이터 행 판정은 숫자형 칸 비율 규칙이다. 숫자가 거의 없는 데이터 표는 머리글을 붙이지 않고 칸 구분만 한다.
- run 분할은 글자 폭 추정이다. 여유 3pt 안쪽은 나누지 않는다.
- 표 복원으로 본문이 약 29% 늘었다(이 공고 기준). 임베딩 비용과 조각 수가 늘어난다.

# R07 예외 목록 해석 지침 보완 (Q13)

2026-11-11. `codex/v02-exception-list-rule`의 로컬 구현·검증 기록이다. 실제 모델 답변 재측정·유료 호출·재색인은 이번 변경에 포함하지 않는다. 커밋·푸시·PR은 사용자 승인 전에는 하지 않는다.

## 문제

[첫 재평가 후속](v0.2-r07-first-run-fixes.md) 재측정에서 Q13("청년으로 입주 뒤 만 40세가 되면 나이만으로 갱신계약이 안 되나")에 틀린 답을 확정했다. 28쪽 원문은 다음 구조다.

- 갱신계약자격은 공급대상자별 일반 공급대상자의 신청자격과 동일하다.
- `* 다만, 아래 경우는 제외`
- `- 청년계층의 경우 19세이상 39세이하, …`

즉 갱신할 때 나이는 확인하지 않는 예외다. 모델은 목록 항목을 요건으로 읽고, 실제 원문 문장을 인용해 "40세면 갱신할 수 없다"고 답했다. 인용 문장 자체는 원문에 있어 정확 인용 검증을 통과했다. 검증은 이런 의미 반전을 잡지 못한다.

## 변경

- RAG v2 지침에 목록 범위 규칙(`RAG_LIST_SCOPE_RULE`)을 추가했다. 목록 항목을 쓰기 전에 그 목록을 이끄는 줄을 읽고, 그 줄이 항목을 예외나 제외(예: 다만, 제외, 예외, 적용하지 않음)로 표시하면 요건이 아니라 예외로 설명하라는 내용이다. 이끄는 줄을 항목과 함께 인용하도록 했다.
- 첨부(v1) 지침은 바뀌지 않았다.
- 지침 길이는 292B 늘었다. 최소 입력 설정(4,096)에서도 짧은 출처 v2 prompt가 들어가는지 확인하는 기존 시험이 통과한다.
- 서버 검증 규칙은 바뀌지 않았다. "예외 목록 항목을 인용하면 이끄는 줄도 인용해야 한다"를 서버가 강제하는 것은 문서 구조 판정이 필요해 이번 범위에서 제외했다.

## 검증

- 시험: RAG v2 지침에 규칙이 들어가고 첨부 v1 지침에는 들어가지 않는지 확인한다. 수정 전 코드에서 실패함을 확인했다.
- `pnpm lint`, `pnpm build`, `pnpm test`(710개 통과, opt-in DB suite 334개 건너뜀), `pnpm test:deployment`(53개) 통과.
- 실제 모델이 규칙을 따르는지는 시험하지 않았다. 지침은 모델 동작을 보장하지 않는다.

## PR #55 리뷰 보완

- **면제와 자격 제외 구분:** 처음 규칙은 "제외" 표시만 보고 항목을 모두 요건이 아니라고 했다. 공고문의 "다음에 해당하는 자는 제외"는 자격을 막는 조건이므로 반대로 읽힐 수 있었다. 지금은 요건·확인을 면제하는 목록의 항목은 예외(요건 아님)로, 대상을 자격에서 빼는 목록의 항목은 자격 제한으로 설명하게 한다.
- **이끄는 줄이 없는 경우:** 근거는 일부 구간만 보내므로 이끄는 줄이 빠질 수 있다. 이때는 항목의 성격(요건·예외·제한)을 정하지 않고 그 판단을 거절하고 followUps에 둔다(v2 부분 거절). 근거 선택 단계에서 이끄는 줄을 찾아 넣는 것은 문서 구조 추측이 필요해 하지 않았다.
- 규칙은 349B다(처음 292B). 최소 입력 설정 4,096에서 가장 긴 짧은 출처 v2 prompt가 약 4,087B로 여유가 약 10B다. 처음 작성한 609B·364B 문구는 이 시험을 넘어 줄였다.
- 시험은 두 경우와 이끄는 줄 부재 문구가 들어가고 이전의 일괄 "NOT requirements" 문구가 빠졌는지 확인한다. 수정 전 코드에서 실패함을 확인했다.
- `pnpm lint`, `pnpm test`(710개 통과, opt-in DB suite 334개 건너뜀) 통과. 실제 모델이 두 경우를 구분하는지는 시험하지 않았다.

## 재측정

- 대상: Q13. 같은 지침이 모든 RAG 질문에 들어가므로 확인용으로 Q07·Q12를 함께 묻는다. 자격 제외 목록이 있는 질문(예: 신청자격 제외 대상)도 하나 함께 확인한다.
- 그래도 Q13이 틀리면 같은 근거로 추론 강도 `low`와 `medium`을 비교한다(유료, 별도 승인).

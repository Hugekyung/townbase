# C01/C04 — 실제 모델 연결·비용 제어 착수안

2026-10-25. main `d42a894`(PR #38 병합)을 동기화하고 `codex/v02-c01-c04-model-execution` 브랜치를 만들었다. 이 문서는 2026-10-25 작성한 착수안이며, 2026-10-26 사용자가 Luna 기본·Sol 선택을 승인했다. 현재 구현/검증 상태는 [후속 기록](v0.2-c01-c04-model-execution.md)을 따른다. 실제 계정 호출·품질 검증 완료를 의미하지 않는다.

## 1. 모델 선택 제안 — 2026-10-26 사용자 승인

공식 문서를 2026-10-25에 조회했다. 아래는 일반 글로벌 Standard 텍스트 호출의 USD/100만 tokens 기준이며 Batch/Flex/Fast/지역 가산·도구 요금은 섞지 않았다. 계정 가용성과 한국어 출처 답변 품질은 실측 전이다.

| 역할 제안 | 모델 | 입력 | 캐시 읽기 | 캐시 쓰기 30분 | 출력 |
| --- | --- | ---: | ---: | ---: | ---: |
| 기본 답변 후보 | `gpt-6-luna` | $0.10 | $0.01 | $0.125 | $0.50 |
| 관리자 선택 상위 후보 | `gpt-6.1-sol` | $2.00 | $0.10 | $2.50 | $10.00 |
| 기존 확정 임베딩 | `text-embedding-3-small` /1536 | $0.02 | 해당 없음 | 해당 없음 | 해당 없음 |

근거: [Luna](https://developers.openai.com/api/docs/models/gpt-6-luna), [Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [임베딩](https://developers.openai.com/api/docs/models/text-embedding-3-small), [가격](https://developers.openai.com/api/docs/pricing).

비용을 우선하는 기본 후보를 Luna로 두고, 복잡한 답변을 위해 관리자가 Sol을 직접 선택하는 안을 추천한다. 이는 가격과 제품 목표에 근거한 설계 판단이며 Luna가 Townbase 품질 기준을 이미 만족한다는 주장이 아니다. 모델 자동 전환·실패 시 상위 모델 재호출은 하지 않는다. 관리자 설정은 구현·검증한 지원 목록으로 제한한다. 최초 선택뿐 아니라 변경값도 저장·재조회한다. 임베딩 모델/차원 변경 API는 만들지 않는다.

두 답변 후보 모두 제품 입력16,000·출력4,096 tokens를 상한으로 사용하고, 추론 강도는 우선 low를 비교 기준으로 제안한다. 사용자가 조절 가능한 값은 모델별 지원 범위와 제품 상한을 함께 검사한다. 모델의 큰 context window를 제품 상한으로 사용하지 않는다. SDK/요청 parameter의 정확한 지원은 구현 시 reference와 대조한다. [GPT-6 사용 안내](https://developers.openai.com/api/docs/guides/latest-model)

## 2. 구현 순서와 실제 연결 지점

1. 모델 선택이 확인되면 지원 모델·API·가격표 버전과 설정 계약을 기록한다. 임베딩은 `/v1/embeddings`, 답변은 `/v1/responses`의 고정 OpenAI endpoint를 사용한다.
2. `packages/database/prisma/`에 현재 필요한 모델/한도 설정·월별 비용 상태·호출 기록 저장을 추가한다. 설치/요청 식별과 DB 제약을 두고, migration과 `deployment/runtime-role.mjs`의 최소 권한·우회 검사·readiness 검사를 함께 변경한다. 원문/Key를 비용 기록에 저장하지 않는다.
3. `apps/api/src/model-integration/`에 설정 저장/조회와 호출 전 비용 예약·정산을 연결한다. 기존 `AuthService.sensitiveOperation`의 재인증/감사 계약을 유지한다. 미설정 예산·미확인 가격·잘못된 모델이면 호출하지 않는다.
4. 실제 네트워크 경계를 단일 서비스로 둔다. 저장된 설치·사용자 범위를 검사하고 활성 Key/전송 정책/모델·비용을 확인한 뒤 호출한다. 원격 호출 대기 동안 장시간 DB transaction을 유지하지 않는다. 임베딩·RAG·첨부 용도를 분리하고 첨부 유래 내용을 임베딩에 보내지 않는다.
5. C02 연결 검사도 같은 비용·전송 경계를 사용한다. Key 저장을 연결 성공으로 표시하지 않고, 결과는 사용한 Key 버전/모델과 연결해 교체·설정 변경 후 과거 성공을 재사용하지 않는다.
6. 설정·호출 상태/사용량은 인증된 설치 범위에서 실제 저장 후 재조회한다. 이번 C 작업으로 기존 v0.1 채팅/Connector/MCP를 운영 활성화하지 않는다. 파일 색인은 D, 실제 출처 답변/대화는 E, 첨부는 F, 설정 웹 통합은 G와 연결한다.

## 3. 비용·중복·실패 계약

- S11의 운영자 명시 예산·80% 안내·100% 신규 호출 차단을 적용한다. 개발 기준 $20/월은 운영 설정의 자동 기본값이 아니다. 임베딩과 답변을 같은 설치 한도에 합산한다.
- 요청 ID를 설치에 묶고, 같은 ID/같은 입력은 기존 상태를 반환한다. 같은 ID의 다른 입력은 거절한다. 동시 요청은 DB에서 비용을 원자적으로 예약해 한도를 함께 통과하지 못하도록 한다.
- 예약은 입력 상한·최대 출력과 해당 요청에서 가능한 캐시 쓰기 요금을 고려한다. 금액은 정수 최소 단위 또는 정확한 decimal로 계산한다. 부동소수점 반올림으로 한도가 줄어들지 않게 한다.
- 원격 전송 전 실패와 전송 후 상태 불명을 구분한다. 전송 후 timeout·연결 단절·응답 파싱/정산 실패는 비용0으로 풀지 않고 미확인 금액을 유지한다. 재시작도 자동 유료 재호출의 근거로 사용하지 않는다. 월이 바뀌어도 이전 호출의 미확인 비용을 삭제하지 않는다.
- 확실한 usage가 있으면 입력·캐시 읽기/쓰기·출력으로 정산한다. 캐시 쓰기는 입력 단가에 별도 가산하는 방식이 아니라 해당 토큰의 대체 단가다. 지원하지 않는 usage/가격 상태를0원 처리하지 않는다. 공급자 청구와의 차이를 설명한다. [캐시 요금·usage](https://developers.openai.com/api/docs/guides/prompt-caching)
- 답변 출력 상한은 추론도 포함한다. `incomplete`이거나 보이는 답변이 없어도 토큰 비용이 발생할 수 있다. 이를 정상 완료나 근거 부족으로 바꾸지 않는다. 90초 timeout과 답변 동시1개·분당10회도 실제 경계에서 검사한다. [추론·출력 제한](https://developers.openai.com/api/docs/guides/reasoning)
- 답변 요청은 `store:false`, foreground, 도구·외부 file-search/vector-store 없이 시작한다. 공급자 보안 로그/캐시 보관까지 없어지는 것으로 설명하지 않는다. [공급자 데이터 보관](https://developers.openai.com/api/docs/guides/your-data)

## 4. 검증과 착수에 필요한 확인

구현 시험은 실제 유료 호출 없이 먼저 완료한다. 공식 응답 계약의 합성 HTTP 서버/fixture, 별도 격리 DB와 실제 제한 계정을 사용한다. 운영 경로는 fake/hash embedding으로 대체하지 않는다.

| 경계 | 확인할 결과 |
| --- | --- |
| 접근·재인증 | 미인증/다른 설치·폐기/만료 세션·잘못된 비밀번호 거절, 설정과 감사 원자성 |
| 전송 | 독립 허용 플래그·본문/파일명 비밀 검사·고정 endpoint·redirect 금지, 차단 시 외부 요청0건 |
| 모델·usage | 지원 목록 외 모델/차원·손상 응답·누락/이상 usage·incomplete 명시 오류, 조용한 fallback 없음 |
| 비용 | 예산 미설정/미확인 가격·캐시 요금·한도 직전 동시 요청·80/100%·입출력/임베딩 합산 |
| 중복·재시작 | 동일 요청1회 전송, 다른 입력 충돌 거절, 전송 후 timeout/재시작의 예약 보존·readback |
| DB·배포 | 실제 migration·열별 최소 권한·우회 거절·준비 상태·서비스 재시작 재조회 |

실제 호출 시험은 **별도 준비한 Key 경로·계정 사용 권한·시험 비용 상한**을 확인한 뒤 합성 입력으로만 진행한다. Key 원문을 채팅/문서/로그에 기록하지 않는다. 계정 접근·사용량·한국어 품질 검증 전에는 실모델 완료로 표시하지 않는다. 착수안 작성 당시에는 유료 호출을 수행하지 않았다. 2026-10-26 후속 실계정 검증3회와 정리 결과는 [구현 기록](v0.2-c01-c04-model-execution.md)을 따른다.

2026-10-25 모델 선택 확인을 요청했고 2026-10-26 승인받아 구현했다. 커밋·푸시·PR은 구현/검증 요약 뒤 별도 사용자 승인을 따른다.

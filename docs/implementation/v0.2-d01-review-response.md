- `pnpm build`, `pnpm lint`, `pnpm db:validate`와 `git diff --check` 통과. schema validate는 명시적 dummy URL을 사용한다.
- 파일 시험36개에는 ZIP invalid_format/archive_limit 분리와 PDF punctuation 보존이 포함된다. 저장 실패 시험11개에는 write/sync/close·중복 close 실패·open 실패·unlink 실패·root/missing/symlink/read 오류가 포함된다. 제어 시험11개는 error→close 사이 슬롯 보존과 watchdog/kill 경쟁을 포함한다. 이들은 API346개에 포함된다.
- 실제 DB는 DROP/CREATE/reset 없이 기존 D01 상태에 후속 migration을 적용했다. 첫 실행은 이전 fixture를 정리한 뒤 통과했다. 그 뒤 작업공간만 생성하고 임시 rejecting CHECK를 남겨 중단 시험을 재현했으며 두 번째 실행도 통과했다. 매회 같은 DB에서 실제 파서36+DB17=53개가 통과했다. 최종 Installation/Session/FileVersion/fixture Workspace count는 모두0이었다.
- DB는 문자열/소수 codePoints, 빈/비배열 segments를 거절했다. envelope만 통과하는 malformed segment·본문 글자 수 불일치·잘못된 출처 위치는 인증된 재조회에서 거절했다. 새 인덱스의 실제 카탈로그 정의를 확인했다.

- 실제 Linux amd64 에뮬레이션 production 이미지의 비특권·read-only root·network none에서4형식 추출/원본 bytes 재조회/삭제가 통과했다. native 장비 성능·HTTP 업로드 E2E가 아니다.

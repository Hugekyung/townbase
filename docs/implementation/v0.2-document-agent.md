## 제공하는 흐름

등록/색인한 파일로 질문하면 검색, 현재 접근/전송 검사, 실제 본문 전달, 출처 답변 또는 거절, 대화/Gap 저장을 실행한다. 결과와 근거는 별도 요청 및 API 재시작 후 조회한다. 기본 Agent 설정과 C의 지원 모델/Key/비용 예약 경로를 사용한다.

| 경로 | 계약 |
| --- | --- |
| POST /rag/questions | requestId UUID v4, question 최대4,000 Unicode code points, requestedMode. 선택적으로 conversationId와 historyRequestIds |
| GET /rag/questions/:id | 소유자의 저장 상태·결과·사용량/비용·현재 유효한 출처 조회 |

모든 경로는 공통 관리자 인증·Host/Origin·설치/소유 검사와 no-store를 적용한다. 신원은 세션과 Installation에서 만든다. DTO/헤더의 workspaceId는 접근 권한을 부여하지 않는다.

POST는 완료 후200, 중복 요청의 기존 실행이 진행 중이면202다. 상태는 running/answered/refused/failed/interrupted다. 접수 후 모델 장애·전송 불허·예산 부족은 failed와 errorCode로 저장한다. 입력/신원/충돌/동시 실행 제한 등 접수 오류는 HTTP400/401/403/404/409/429로 거절한다. 불명 비용은 null과 예약 금액으로 표시한다.

새 대화는 conversationId를 생략한다. 후속 질문은 소유 대화 ID와 이전 requestId 최대3개를 historyRequestIds에 전달한다. 명시한 순서로 결과를 다시 확인해 사용하며 임베딩에는 이번 질문만 전달한다. 이력의 출처가 변경되거나 만료되면 사용을 거절한다. RAG 전용 저장/엄격 입력으로 첨부 ID/결과의 자동 편입을 차단한다.

## 검색과 답변

기존 rag-core의 규칙 기반 mode/strategy/ranking과 agent-core의 출처 규칙·모드별 prompt를 재사용한다. auto에 한국어 문서 누락/이력 질문 규칙을 추가하고 일반 질문에는 기존 onboarding 기본 규칙을 적용한다. onboarding/product_history/documentation_gap을 후보 metadata·우선순위·답변 지침에 반영한다. 예약 change_impact는 새 API 입력에서 거절하고 기존 enum/fixture는 보존한다.

등록 파일의 uploaded_file과 knowledgeTypes=unknown을 후보로 허용한다. 알려진 knowledgeTypes는 모드 조건을 적용한다. Agent selected 목록은 SQL 후보 조회부터 적용한다. 삭제/제외·현재 버전·active 상태·최신 추출 성공·색인 digest·scope·고정 small/1536을 D05 공통 조건으로 검사한다. sourceType/knowledgeTypes/domainTags/status/sourcePriority와 실제 requestedMode/resolvedMode를 전달·저장한다.

초기 선택은 후보20개, 모드 ranking, 근거 최대5개·8,000 UTF-8 bytes다. 완전한 조각을 예산 안에서 선택하고 조각 본문을 자르지 않는다. 기존 비교값을 근거로 최고 선택 조각의 raw cosine 0.45 이상과 모드 상위3개 후보의 raw 평균0.40 이상을 초기 판정에 채택했다. 평균은 약한 후보 제거 전 계산하며 metadata boost를 판정값에 섞지 않는다. 정답 집합의 검색/거절 품질은 J에서 실측한다.

고정 서버 지침은 Responses instructions로 분리하고 Agent 설정은 이름/목적/용어/표현 선호로 전달한다. 실제 source.content와 원문 위치를 입력에 넣는다. 반환 JSON은 주장별 sourceId/quote가 실제 선택 조각에 존재하는지 확인한다. 상충 설명은 서로 다른 두 문서의 인용을 요구한다. 확정할 수 없는 상충도 양쪽 근거와 거절/Gap으로 저장한다. 인용 존재 검사와 주장의 의미적 타당성 평가는 구분하며 후자는 J에서 실측한다.

instructions/input 우선순위는 [OpenAI 공식 prompt 문서](https://developers.openai.com/api/docs/guides/prompt-engineering)를 확인했다. C는 두 필드를 전송 검사·상한·동일 요청 digest에 포함한다. 지침이 없는 기존 C 호출의 digest도 보존한다.

## 호출·권한·시간 경계

임베딩/답변 호출 UUID는 질문 requestId와 용도에서 결정한다. 재전송은 저장 상태를 읽는다. 보관 종료 후에도 같은 UUID의 ModelCall이 있으면 재사용을 거절한다. 새 UUID의 수동 재시도에는 비용이 다시 생길 수 있다.

전체 질문 동시1개·접수 분당10개·전체90초, 입력/출력은 C의 최대16,000/4,096과 임베딩 입력 상한을 적용한다. 입력 설정은 PR #47 보완 후4,096~16,000이며 기본16,000은 유지한다. 최솟값은 고정 지침과 짧은 질문/근거를 위한 것으로 최대 길이의 설정·이력·문서까지 모두 들어간다는 보장은 아니다. UTF-8 bytes+framing 기반의 보수적 한도이며 정확한 tokenizer가 아니다. 질문4,000자 안에서도 byte/context 한도를 먼저 초과할 수 있다. 초과는 실패로 기록하며 지침/근거를 몰래 자르거나 예산을 늘리지 않는다. 질문 JSON은 선인증 뒤64KB를 허용하고 다른 일반 API는8KB다. 압축 입력을 거절하고 질문 본문 슬롯은 본문 완료 시 해제해 중복 상태 조회를 허용한다.

C master I/O 전/후 입장과 게시 시점에 최신 세션·Agent id/revision·모델 설정 digest·소유 자료/버전/scope/색인을 재검사한다. JSON escaping 전의 질문·Agent 선호·이력·근거 원문도 정책/비밀 패턴을 검사한다. 민감한 질문은 실행 저장 전에 차단한다. 파일/네트워크 I/O를 인증 transaction에 넣지 않는다.

전체 deadline은 C 호출에 전달한다. 취소 처리가 늦은 의존성에도 timeout 상태로 응답하고 늦은 게시를 running CAS/deadline으로 막는다. 종료는 취소 후 최대1초 정리를 기다리고 재시작 시 진행 상태는 interrupted가 된다. 전송 후 불명 비용은 C 예약을 유지하며 실제 usage가 확인되면 비용을 기록한다.

## PR #47 리뷰 보완 (2026-11-08)

- 지연 시험은 임베딩/검색에 성공한 뒤 유효한 답변만 지연한다. 시간 내 게시 성공과90초 뒤 게시 차단을 함께 확인했다. 게시 직전 AbortSignal 검사를 임시 제거하면 늦은 complete 호출 때문에 시험이 실패하고, 복구하면 통과함을 확인했다.

- BasicAgentResult는 answered의 실제 model을 string 필수로 하고 refused만 null을 허용한다. 타입 회귀 검사를 함께 추가했다.

# v0.2 RAG 답변 계약 v2 — 묶음 B R05

2026-11-11. `codex/v02-rag-answer-contract`의 로컬 구현·검증 기록이다. [계획](v0.2-rag-quality-improvement-plan.md) §8 R05를 구현했다. 실제 모델 답변 품질 재측정(R07)과 문서 재색인은 포함하지 않는다. 사용자 승인 전에는 커밋·푸시·PR을 만들지 않는다.

## 계약

| 항목 | v2 (`rag_answer`) | v1 (첨부·과거 RAG 행) |
| --- | --- | --- |
| 공급자 schema | `townbase_rag_grounded_v2`: `isAnswerable`, `reason`, `claims`, `conflicts`, `followUps` | `townbase_grounded_v1` 그대로. 직렬화 문자열 SHA-256 `87a77d38…c614`를 시험으로 고정 |
| 저장 | `result.contractVersion = 2`를 명시 저장 | 버전 키 없음 |
| 거절의 부분 사실 | `isAnswerable=false`여도 `claims` 허용. 각 사실은 S번호·정확 인용 검증 필수 | 거절이면 `claims` 금지(기존 유지) |
| 추가 확인 항목 | `followUps` 최대5개·각300자·제어문자/빈 값 금지. 근거·사실 통로가 아니며 answerable이면 빈 배열 | 없음 |
| 충돌 | 다른 문서 2개, 또는 같은 문서의 겹치지 않는 서로 다른 구간 2개 | 다른 문서 2개(기존 유지) |
| 근거 없음 거절 문구 | "이번에 찾은 등록 문서 근거로는…문서 전체에 해당 내용이 없다는 뜻은 아닙니다" | 기존 문구 |
| 모델 거절 사유 | 모델 reason은 그대로 두고, 그 뒤에 서버 고정 문구 "※ 이번에 찾은 근거 기준이며, 문서 전체에 해당 내용이 없다는 뜻은 아닙니다."를 붙인다. 서버 근거 없음 문구에는 중복하지 않는다 | 변경 없음 |

- 상태는 그대로다. 부분 사실이 있는 거절도 `refused`이며 Gap을 같은 transaction에 저장한다. 부분 근거를 `answered`로 세지 않는다. 기술 실패는 계속 `failed`이고 Gap을 만들지 않는다.
- DB CHECK는 검토 결과 바꾸지 않았다. 기존 CHECK가 `refused`에 `result`/`answer` 필수, `model` NULL 허용(검색 단계 거절)을 이미 강제한다. 새 migration·ACL 변경은 없다.
- 재조회는 `contractVersion`이 있으면 v2 규칙, 없으면 v1 규칙으로 읽는다. 과거 v1 행을 v2로 재해석하지 않는다. 그래서 v1 거절에 사실이 붙은 행은 여전히 거절된다.
- 첨부는 `promptFor`의 기본 계약(v1)을 그대로 쓰므로 지침·schema·입력 상한이 바뀌지 않는다.

## 같은 문서 충돌 판정

현재 색인(`file-index-d04-v3`)은 chunk 본문의 줄과 저장된 `locations` 항목이 1:1이다. 인용 구간을 줄 단위 위치 키(segment·start·end)와 줄 안의 범위로 변환해 비교한다.

- 같은 문장을 두 번 인용하거나 한쪽이 다른 쪽을 포함하면 한 쪽으로 본다.
- 같은 위치 키에서 범위가 겹치면 한 쪽으로 본다. 겹침 분할로 두 chunk에 반복된 단위도 같은 키라서 여기에 해당한다.
- 같은 문구라도 저장 위치가 다르면 두 쪽으로 인정한다.
- 줄과 위치가 1:1이 아닌 이전 색인 배치는 줄 텍스트를 키로 쓰는 보수적 판정으로 대체한다.

## Q08 진단

공개 오류 코드는 `invalid_grounded_response`(502)를 유지한다. 내부 분기는 `GroundingError.detail`로 구분한다: `json`, `schema`, `source_id`, `quote_mismatch`, `answerability`, `conflict_evidence`, `follow_up`. RAG 실패 시 `TOWNBASE_RAG_GROUNDING_<DETAIL>` 고정 코드만 운영 진단 로그(허용 목록)에 남기고 공급자 원문은 저장하지 않는다. 유료 자동 재시도나 모델 전환은 없다.

2026-11-11 R07 첫 재평가 후 `quote_punctuation`·`quote_spacing`을 추가하고 공백만 다른 인용을 허용했다. [후속 기록](v0.2-r07-first-run-fixes.md)을 따른다.

Q08의 원래 실패 분기는 당시 공급자 원문이 남아 있지 않아 이번에 재현하지 못했다. 다음 실제 재측정(R07)에서 위 진단 코드로 분기를 확인한다.

## 웹

- v2 거절에 확인된 사실이 있으면 "일부 근거만 확인" 배지와 안내 문구를 보여준다.
- answered, 사실이 없는 거절, v1 행, 출처가 무효해진 결과에는 배지를 보여주지 않는다.
- 추가 확인 항목은 저장된 답변 본문의 "추가로 확인할 항목" 목록으로 표시되며 복사에도 포함된다.
- 같은 문서 충돌을 포함해 v2 충돌 표기는 "근거 간 충돌"이다.

## 입력 상한

v2 지침과 schema가 v1보다 길다. 최소 입력 설정 4,096에서 짧은 출처 질문의 상한은 v1 약 3,540, v2 약 3,700이다. 첫 v2 문구는 약 4,240으로 최소 설정을 넘어 실DB 시험에서 실패했다. 지침을 압축한 뒤 해당 회귀 시험이 수정 전 실패·수정 후 통과함을 확인했다.

## PR #51 리뷰 보완 (2026-11-11)

- 모델 거절 사유는 범위를 서버가 검증할 수 없으므로, v2 거절 본문에 서버 고정 범위 문구를 덧붙인다(reason 원문·저장 JSON은 그대로). 키워드로 사유를 거절하지 않아 정상 거절이 기술 실패로 바뀌지 않는다. 신규 시험은 문구 상수만 추가한 수정 전 코드에서 실패함을 확인했다.
- 웹 배지 시험의 양성 fixture를 실제 v2 파서가 받아들인 결과(출처·정확 인용 포함)로 바꾸고 출처 인용 표시를 함께 확인한다.
- 같은 문구가 문서의 다른 위치에 있는 경우는 상충 근거가 아니므로 충돌 양쪽으로 인정하지 않는다(계획 §8-4). 리뷰 제안은 반영하지 않았다.

## 상태·중복 구분

인라인 전체83건 중60건 resolved·23건 unresolved다. 이 중 신규6건, 이전17건이며 이전17건 중5건은 outdated다. 미해결 표시만으로 현재 코드 미수정으로 단정하지 않는다. 이전 반복 항목의 코드/대안 대응은 [1차 대응](v0.2-pr48-review-response.md), [2차 대응](v0.2-pr48-round2-response.md)을 따른다. DeletionJournal 중복 등록은 여전히 해당하지 않는다.

봇 최신 review 본문은 신규6개 인라인의 요약이므로 별도6건으로 중복 계산하지 않는다. 전달 댓글2개는 수정/검증 보고이며 새 결함이 아니다. 이번 신규 지적은 파일 위치가 비슷해도 이전 것과 다른 원인이다: basic cleanup 누락은 attachments/retrieval 중복 mkdir와 다르고, cp deadline은 helper 자체 무기한 대기와 다르며, provenance 재개 문제는 SHA 표기의 신뢰 범위 문제와 다르다.

점검 당시 권장 우선순위는 basic 종료 실패의 DB/잠금 정리 → 큰 데이터 복사 deadline → 안전한 이전 계약 재개 → 문서 상태 링크/관측값 증거 정렬이었다. 이5건은 위 수정 커밋에서 반영됐으며 현재 미처리 목록이 아니다. 신규5번은 필수 수정으로 채택하지 않는 것이 적절하다.

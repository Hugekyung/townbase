1. `/tmp/townbase-v02-b01/legacy/prisma/`에 기존7개 migration만 복사하고 upgrade_test DB에 deploy했다. 새 migration을 먼저 적용한 DB에서 업그레이드를 흉내내지 않았다.
2. workspace2개와 기존8개 모델의 합성 행을 넣었다. chunk에는 실제1536차원 벡터도 저장했다. 적용 전/후 각 테이블을 ID 순서의 JSON으로 읽고 전체 내용이 같은지 비교했다.

## 4. 실행 조건과 남은 제한

- DB 통합 시험은 테스트용 DB에서만 실행한다. `installation.integration.spec.ts`는 connect 전에 DB 이름 안전 검사를 한다. DB 없는 단위 시험은 `--testPathIgnorePatterns=integration.spec.ts`로 **모든** DB 통합 suite를 제외한다. A04의 과거 파일명 하나 제외 명령과 구분한다.
- fresh DB: `DATABASE_URL`을 전용 test DB로 지정 → `pnpm db:deploy` → `pnpm db:seed` → `pnpm db:test` → `pnpm connectors:test`. API Jest도 같은 URL을 쓰고 유료 API 대신 fixture/mock만 사용했다.
- upgrade/restore 시험은 각 DB를 따로 사용했다. 초기 fixture는 기존8개 모델 모두·workspace2개·벡터1536차원을 포함한다. 정확한 조작은 위 순서와 임시 실행 로그를 따르며 공개/실데이터 DB에 그대로 재사용하지 않는다.
- `git diff --check` 및 관련 문서 링크 재조회 통과. 이번 전달의 실제 commit은 Git 이력으로 확인한다. 사용자 요청으로 PR은 생성하지 않는다.

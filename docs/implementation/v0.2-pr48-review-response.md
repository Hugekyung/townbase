# PR48 리뷰 대응 — 로컬 검증

기준 `2a30038`, `codex/v02-final-basic-release`. 사용자 지시로 타당/부분 타당59건을 대응했고 중복 등록 오판1건(#32)은 제외했다. 2026-11-08 사용자가 검증 요약 후 커밋/푸시/PR 댓글 전달을 승인했다. 스레드 resolve는 자동 수행하지 않는다. 개인 interview.md는 수정하지 않았다.

## 핵심 변경과 검증

- 삭제 의도를 즉시 적용하고 불확실한 DB/기록 상태에서는 인증·readiness를 차단한다. 실제 DB trigger로 실패를 유도해 자료/채팅503→장애 제거→새 API startup replay→404를 확인했다.
- 생성/복원 한도 대칭, 복원 전 전체 journal 검증, 파일 충돌 보존과 stdin EPIPE 정리를 보완했다.
- 미확인 요청 목록/선택된 중지 대상/첨부 availability·시간순 이력/Agent 폼과 설정 CSS를 정리했다.
- Prisma unique/index/update 정책은 기존 SQL에 맞췄다. 적용한 migration은 재작성하지 않았다.
- 과거 실계정 결과는 소급 수정하지 않았다. 당시 commit 미존재·migration 시점·latency 후처리를 명시하고 새 runner의 재개/파일 hash/출력/신호 경계를 강화했다. 이번 추가 유료 호출0회.

검증: build/lint·Prisma generate/validate, API556개(기본 opt-in323개 skip과 구분), database20개/connectors72개, 배포33개(백업/프로세스9개 포함), 실제 제한 DB 첨부/채팅/운영23개·RAG27개·권한82개. 새 API 시험은 DB 없는 실패 경계15개와 웹 요청 복구7개, 추가 진단1개를 포함한다. 집계는 [verification.json](evidence/v0.2-pr48/verification.json)을 따른다.

브라우저: 합성 계정 로그인, 햄버거 개폐 뒤 초안 유지, 채팅/설정 분리 및 수정한 설정 폼 표시 확인. DOM maxlength/폭 자동 확인은 도구 selector timeout으로 완료하지 않았고, 이를 브라우저 실측 통과로 세지 않았다. 별도 build·입력 검증·API 시험과 구분한다. [화면](evidence/v0.2-pr48/settings.png). 종료 신호3종은 실제 wrapper에 네트워크 없는 가짜 자식을 연결해 확인했다.

## 검증의 한계

40GiB 실제 dump나 모든 오래된 릴리스 snapshot을 새로 생성해 복원한 것은 아니다. 공유 한도의 경계 metadata/기존 사본 보존/평문 정리/기존 정상 round-trip과 이전 실제 runtime 복원 증거를 구분한다. 새 runner로 유료120문항을 다시 호출하지 않았고, 기존 수치를 수정 후 전체 품질 측정으로 주장하지 않는다. AT/OP의 부분 확인/N/A는 [평가 기록](../evaluation/v0.2/final-2026-11-08.md)에 남긴다.

이 대응표의 번호는 원래60개 인라인 스레드 순서다. 초기 판단은 [audit](v0.2-pr48-review-audit.md)에 보존했다. 원격 스레드 resolve는 자동 수행하지 않으며, 승인받은 대응 요약은 PR 대화 댓글로 전달한다.
